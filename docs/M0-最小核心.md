# M0 最小核心 · 设计与运行

## 目标

用 Jenkins 自举一套可运行的底座：**权限管理服务 + 路由注册服务 + Caddy + Nexus + 备份**，并由**参数化 Job** 驱动各服务的部署/备份。

## 数据面 / 控制面 / 运维面

```
用户 → OAuth2 Proxy（认证）→ Caddy（路由）→ 各服务        # 数据面
config/routes.yaml → router（render.py）→ Caddy admin /load  # 控制面
Jenkins deploy-service / backup-service（参数化 Job）        # 运维面
```

## 本地运行

```bash
cp .env.example .env
make render                 # routes.yaml -> out/Caddyfile
make deploy                 # 起底座
make test                   # render.py 语法自检
```

## 参数化 Job

| Job | 参数 | 说明 |
|---|---|---|
| `deploy-service` | SERVICE(choice) / ENV(choice) / VERSION / PORT / DOMAIN / DRY_RUN | 部署单个服务 |
| `backup-service` | SERVICE(choice) / BACKUP_TARGET(choice) / RETENTION_DAYS | 备份单个/全部服务 |

### JJB 校验与推送

在 `.env` 中填写 `JENKINS_URL`、`JENKINS_ADMIN_ID`、`JENKINS_ADMIN_PASSWORD`
（推送时也可使用 Jenkins API token），并为 `GITHUB_USER` / `GITHUB_TOKEN` 填写
可读取本 private 仓库的账号与 PAT；不要提交 `.env`。

```bash
docker compose build jjb      # Python 3.11 + JJB，固定 setuptools<81
make jobs-test               # 离线渲染 2 个 Job，不访问 Jenkins
make jobs                    # 推送到 Jenkins；scripts/deploy.sh --push-jobs 等价
```

两条 Make 命令先由 `scripts/gen-jjb-conf.sh` 校验 `.env` 的三个 Jenkins 必填值，
再生成权限为 `0600` 的 `.jjb/jenkins_jobs.ini`；`.jjb/` 已忽略。
`jobs-test` 的 XML 在 `.jjb/rendered/{deploy-service,backup-service}/config.xml`。
`jjb` 使用 `tools` profile，普通 `docker compose up -d` 不会启动它；
使用 host 网络，以便默认的 `localhost` Jenkins URL 可从工具容器访问
（Linux 原生支持；Docker Desktop 需启用 host networking）。
推送 URL 必须直接可达 Jenkins API，不能被 OAuth2 交互登录拦截；若网关要求
登录，应使用受限的管理网络入口，不要为 JJB 放开公众匿名访问。

### Jenkins 与 agent 前提

Jenkins 需安装 Configuration as Code、Pipeline（含 Shared Groovy Libraries）、
Git、Credentials Binding 插件。Compose 将 `.env` 的凭据传入 Jenkins，
JCasC 注册 `orgflow-shared`（`main` 分支、`shared-library` 子目录），并创建：

| Credentials ID | `.env` 来源 | 用途 |
|---|---|---|
| `github-token` | `GITHUB_USER` / `GITHUB_TOKEN` | 共享库检出、Job 私库 checkout |
| `ldap-admin-password` | `LDAP_ADMIN_PASSWORD` | deploy 的 `withCredentials` |
| `oauth2-client-secret` | `OAUTH2_CLIENT_SECRET` | deploy 的 `withCredentials` |
| `oauth2-cookie-secret` | `OAUTH2_COOKIE_SECRET` | deploy 的 `withCredentials` |

修改 `.env` 后需重建 Jenkins 容器以更新环境变量，再加载 JCasC；单独
`make jobs` 不会安装插件或更新 JCasC。保留现有 Jenkins 镜像，不在此任务安装插件。

两个 Job 在标签为 `orgflow-docker` 的可信 agent 上执行。该 agent 需提供
Bash、Git、Python 3、Docker CLI / Compose，以及目标 Docker daemon 的访问权限。
在 checkout 的工作区预置不入库的 `.env`（dev）或 `.env.staging` / `.env.prod`；
非 dev 不会静默回退到 dev 配置。部署凭据绑定的环境变量优先于 env 文件中的同名值。
Docker bind mount 要求 agent 工作区在 daemon 主机的相同绝对路径可见，
本地备份目录也必须持久化。不要在不可信、共享执行器上运行有 Docker/凭据权限的 Job。

JJB 的 inline Pipeline 字段为 `dsl`，Groovy 花括号在 YAML 中使用 `{{` / `}}`。
Pipeline 顶层 `scm` 不会自动检出代码，因此 DSL 另行显式执行带
`github-token` 的 `checkout(scm)`，然后在当前工作区调用共享库。

`DRY_RUN=true` 只输出部署命令，不绑定部署凭据、不执行 shell 或操作容器
（加载共享库与 Job checkout 仍会访问 Git）。实部署复用 `scripts/deploy.sh --service`，
仅启动所选服务，不顺带启动依赖；首次启动依赖请先执行 `make deploy`。
`VERSION` 留空保留现有版本，非空只支持已有可配置版本的 Jenkins/Nexus；
`PORT` 只覆盖 Caddy 网关端口。M0 是路径路由，不支持 `DOMAIN` 覆盖，非空明确报错，
域名需另行配置 routes/Caddy。`ENV` 选择同一目标底座使用的 env 文件，不创建隔离环境。
备份当前仅支持 `BACKUP_TARGET=local`；不再提供未实现的 Nexus 目标。
`RETENTION_DAYS` 为 0–99999 的整数，清理只作用于本次所选服务的归档；
卷不存在或备份失败时 Job 失败，不生成“成功”的空备份。

脚本回归 `make test`（路由渲染 / LDIF 导入 / Job 定义）；共享库行为回归
`make test-groovy`（需要 groovy，缺失则自动跳过）。`make jobs-test` 只在本地渲染
XML、不连接 Jenkins，因此**不需要 .env**；真正推送用 `make jobs`。

## 验收（M0）

- [ ] `make deploy` 一条命令起 Jenkins + 权限 + 路由 + Caddy + Nexus
- [ ] 改 `config/routes.yaml` 后 `make render`，Caddy 热加载新路由，旧路由不中断
- [ ] `deploy-service` 可按参数拉起指定服务
- [ ] `backup-service` 产出可恢复的 `.tgz`
- [ ] 未登录访问受保护路径被拦截
