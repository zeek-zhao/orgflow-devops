# M0 最小核心 · 设计与运行

## 目标

用 Jenkins 自举一套可运行的底座：**权限管理服务 + 路由注册服务 + Caddy + Nexus + 备份**，并由**参数化 Job** 驱动各服务的部署/备份。

## 数据面 / 控制面 / 运维面

```
用户 → Caddy（TLS 站点）→ OAuth2 Proxy（认证）→ 各服务          # 数据面
config/routes.yaml → router（render.py）→ Caddy admin /load      # 控制面
Jenkins deploy-service / backup-service / restore-service        # 运维面
dnsmasq（容器内 DNS）+ 宿主/局域网 hosts 片段                     # 名字解析面
```

域名模型见 [ADR-13 域名路由](ADR-13-域名路由.md)：每个服务一个站点
`https://<subdomain>.<GATEWAY_DOMAIN>`，默认 `org-devops.com`。

| 站点 | 服务 | 需要登录 |
|---|---|---|
| `home.<domain>` | homepage（统一入口，从这进） | 否 |
| `jenkins.<domain>` | Jenkins | 是 |
| `nexus.<domain>` | Nexus | 否 |
| `ldapadmin.<domain>` | LDAP Admin | 是（#36 起网关鉴权） |
| `dex.<domain>` | Dex | 否 |
| `auth.<domain>` | OAuth2 Proxy | — |

网络拓扑、固定 IP 表与分层排查决策树见 [网络架构](network/arch.md)；
每个服务的使用/部署/排查见 [`docs/services/`](services/)。

## 本地运行

```bash
make doctor                 # 只读环境自检
make deploy                 # 初始化 .env、渲染、分批启动、等待健康、自检端点
make hosts                  # 生成 /etc/hosts 片段（域名解析必需）
make ca                     # 导出并安装 Caddy 内部 CA 根证书（自签 TLS 必需）
make test                   # 路由 / LDIF 导入 / 部署 / Job 回归
```

## 干净环境自举

前置条件：Bash、Python 3（无需第三方库）、curl、可访问的 Docker daemon 和
Docker Compose v2；账号需有 Docker socket 权限。主机网关端口默认 **80/443**
（`GATEWAY_HTTP_PORT` / `GATEWAY_HTTPS_PORT` 可改），应可绑定；需能访问
Docker Hub、GHCR、Quay，并预留镜像下载空间（建议至少
5 GiB，另留 Jenkins/Nexus 持久化数据空间）。Docker bind mount 要求工作区
在 daemon 主机的相同绝对路径可见。

**GHCR 上的 13 个包全部 public**，拉取不需要 `docker login`，也不需要 PAT；
需要凭据的只有推送侧（工作流内置 `GITHUB_TOKEN`）。`USE_GHCR=1` 的路径
完全匿名可用，`tests/bats/18_public.bats` 会逐个匿名取 manifest 作为回归闸门。

域名解析由两段组成：**容器内**走 dnsmasq（`*.org-devops.com` → Caddy 固定 IP
`172.31.0.10`），**宿主机与局域网机器**走 hosts 片段（`make hosts`）。
局域网其他机器访问时用 `bash scripts/gen-hosts.sh <本机IP> --write` 或把片段
粘到它的 hosts 文件；不改路由器 DNS 是有意为之，避免影响其他设备。

先运行 `make doctor` 查看 Docker/Compose 版本、daemon 连通性、端口占用、
环境文件、磁盘余量及本地镜像；它不会启动容器，也不会拉取或构建镜像。
缺少 `.env`、镜像尚未缓存会显示提示，这是首次部署的正常情况。
已有当前 Compose 项目占用网关端口会单独标注；其他端口冲突须先解决。

执行 `make deploy` 即可自举。默认 dev 的 `.env` 不存在时，从 `.env.example`
派生并生成 Jenkins/LDAP 管理员密码、OAuth2 client secret（各 32 随机字节），
以及 32 字符 ASCII cookie secret（32 字节字符串）。文件权限为 `0600`，
只提示「已写入 .env，请妥善保存」，不打印密钥；已有 `.env` 原样保留。
不要提交 `.env`。已有持久化 LDAP 数据时须使用与原数据匹配的管理员密码，
随机新密码不会重置已有目录。单服务 Job、自定义 env 文件或 staging/prod 缺少
环境文件时仍明确失败，不会以 dev 配置代替。

启动顺序为 `dnsmasq` → `ldap` → `dex oauth2-proxy` → `router caddy` →
`jenkins nexus ldapadmin homepage`。每批逐服务执行 `up -d --no-deps <构建标志>`，
避免一次并发拉取多个大镜像而难以定位失败；一批全部 healthy 后才启动下一批。
构建标志跟着镜像来源走：默认 `--build`，`USE_GHCR=1` 时 `--no-build`
（镜像钉了 digest，`--build` 会报 `refusing to create a tag with a digest reference`）。
`dnsmasq` 必须最先 healthy：其余容器的 resolver 都指向 `172.31.0.2`。

### 真机部署（213）

213 访问不到 Docker Hub，只能 `USE_GHCR=1`。三条容易漏的：

1. **宿主不解析 `<sub>.<domain>`**：容器内靠 dnsmasq，宿主侧靠 `make hosts` 写的片段。
   没装的话 `make jobs` 这类走宿主网络的工具会 `NameResolutionError`（见 #30）。
2. **旧格式 `.env` 要补 `GATEWAY_HTTP_PORT` / `GATEWAY_HTTPS_PORT`**，并改掉硬编码的
   `JENKINS_URL`；`GATEWAY_PORT` / `LDAPADMIN_PORT` / `ROUTER_PORT` 已无代码引用，可直接删。
3. **历史重写后旧克隆是分叉的**（`ahead N, behind M`），`git pull` 不会快进，
   要 `git fetch && git reset --hard origin/main`。
先建立名字解析与身份服务，再准备路由/网关，最后启动耗时较长的 Jenkins/Nexus。
router 的 `/healthz` 独立于 Caddy admin reload，避免两者启动互相等待。

健康闸门直接检查容器的 Docker health 状态；Jenkins 使用容器内部 `/login`，
不经过认证网关。每个健康等待阶段默认最多 600 秒，可通过
`DEPLOY_HEALTH_TIMEOUT` 调整；`DEPLOY_POLL_INTERVAL` 默认 3 秒。
全部服务最终再次确认为 healthy 后，严格核验
`https://auth.<domain>/ping` 返回 **200**、`https://jenkins.<domain>/` 返回 **302**
（`curl --resolve` 钉住域名，不跟随重定向）。
**未登录时 Jenkins 站点返回 302 是正常的认证跳转，不代表 Jenkins 已就绪。**
成功后输出入口列表、网关端口、`make hosts` / `make ca` 提示、`make jobs` 下一步
和管理员密码在 `.env` 中的位置。
官方 Jenkins 镜像的插件/JCasC 配置前提仍见下文；HTTP 健康不等于已安装 Job
所需插件或已配置私库访问。

拉取、构建、启动或健康检查失败会非零退出，并标明服务、输出
`docker compose ps -a` 和相关服务最近 50 行日志（已屏蔽配置中的密码/密钥）。
镜像拉取失败、尚未创建容器时没有服务日志，应检查同一服务上方的下载错误。
可再次执行 `make doctor`，或在本机查看
`docker compose --env-file .env logs --tail=50 <服务>`；分享日志前自行检查敏感内容。
修复网络、端口、磁盘或配置后重新运行 `make deploy`，无需删除数据卷。

## 参数化 Job

| Job | 参数 | 说明 |
|---|---|---|
| `deploy-service` | SERVICE(choice) / ENV(choice) / VERSION / DRY_RUN | 部署单个服务 |
| `backup-service` | SERVICE(choice) / BACKUP_TARGET(choice) / RETENTION_DAYS | 备份单个/全部服务 |
| `restore-service` | SERVICE(choice) / BACKUP_FILE / CONFIRM | CONFIRM=YES 才停服覆盖恢复 |

### JJB 校验与推送

在 `.env` 中填写 `JENKINS_URL`、`JENKINS_ADMIN_ID`、`JENKINS_ADMIN_PASSWORD`
（推送时也可使用 Jenkins API token），并为 `GITHUB_USER` / `GITHUB_TOKEN` 填写
可读取本 private 仓库的账号与 PAT；不要提交 `.env`。

```bash
docker compose build jjb      # Python 3.11 + JJB，固定 setuptools<81
make jobs-test               # 离线渲染 3 个 Job，不访问 Jenkins
make jobs                    # 推送到 Jenkins；scripts/deploy.sh --push-jobs 等价
```

两条 Make 命令先由 `scripts/gen-jjb-conf.sh` 校验 `.env` 的三个 Jenkins 必填值，
再生成权限为 `0600` 的 `.jjb/jenkins_jobs.ini`；`.jjb/` 已忽略。
`jobs-test` 的 XML 在 `.jjb/rendered/{deploy-service,backup-service,restore-service}/config.xml`。
`jjb` 使用 `tools` profile，普通 `docker compose up -d` 不会启动它；
使用 host 网络，以便从工具容器访问宿主上的网关入口
（Linux 原生支持；Docker Desktop 需启用 host networking）。
域名路由后 `JENKINS_URL` 是 `https://jenkins.<domain>/`，因此：

- 宿主机 `/etc/hosts` 要有对应记录（`make hosts`）；
- 网关是内部 CA 自签，容器内用 `REQUESTS_CA_BUNDLE=/repo/out/ca/root.crt` 校验，
  该文件由 `make jobs` 的前置目标自动 `scripts/ca-install.sh --export` 生成。

推送 URL 必须直接可达 Jenkins API，不能被 OAuth2 交互登录拦截；若网关要求
登录，应使用受限的管理网络入口，不要为 JJB 放开公众匿名访问。

### Jenkins 与 agent 前提

Jenkins 需安装 Configuration as Code、Pipeline（含 Shared Groovy Libraries）、
Git、Credentials Binding 插件。Compose 将 `.env` 的凭据传入 Jenkins，
JCasC 注册 `orgflow-shared`（`main` 分支、`shared-library` 子目录），并创建：

| Credentials ID | `.env` 来源 | 用途 |
|---|---|---|
| `github-token` | `GITHUB_USER` / `GITHUB_TOKEN` | 共享库检出、Job 私库 checkout |
| `ldap-admin-password` | `LDAP_ADMIN_PASSWORD` | deploy 的 `withCredentials` |
| `oauth2-client-secret` | `OAUTH2_CLIENT_SECRET` | deploy 的 `withCredentials` |
| `oauth2-cookie-secret` | `OAUTH2_COOKIE_SECRET` | deploy 的 `withCredentials` |

修改 `.env` 后需重建 Jenkins 容器以更新环境变量，再加载 JCasC；单独
`make jobs` 不会安装插件或更新 JCasC。保留现有 Jenkins 镜像，不在此任务安装插件。

三个 Job 在标签为 `orgflow-docker` 的可信 agent 上执行。该 agent 需提供
Bash、Git、Python 3、Docker CLI / Compose，以及目标 Docker daemon 的访问权限。
在 checkout 的工作区预置不入库的 `.env`（dev）或 `.env.staging` / `.env.prod`；
非 dev 不会静默回退到 dev 配置。部署凭据绑定的环境变量优先于 env 文件中的同名值。
Docker bind mount 要求 agent 工作区在 daemon 主机的相同绝对路径可见，
本地备份目录也必须持久化。不要在不可信、共享执行器上运行有 Docker/凭据权限的 Job。

JJB 的 inline Pipeline 字段为 `dsl`，Groovy 花括号在 YAML 中使用 `{{` / `}}`。
Pipeline 顶层 `scm` 不会自动检出代码，因此 DSL 另行显式执行带
`github-token` 的 `checkout(scm)`，然后在当前工作区调用共享库。

`DRY_RUN=true` 只输出部署命令，不绑定部署凭据、不执行 shell 或操作容器
（加载共享库与 Job checkout 仍会访问 Git）。实部署复用 `scripts/deploy.sh --service`，
仅启动所选服务，不顺带启动依赖；首次启动依赖请先执行 `make deploy`。
`VERSION` 留空保留现有版本，非空只支持已有可配置版本的 Jenkins/Nexus；
网关端口与域名在 ADR-13 之后**不再是 Job 参数**，一律来自 env 文件
（`GATEWAY_HTTP_PORT` / `GATEWAY_HTTPS_PORT` / `GATEWAY_DOMAIN`）。
旧参数 `PORT` / `DOMAIN` 已从 Job 界面移除；共享库仍会对直接传入它们的
调用明确报错，避免调用方以为改了端口而实际什么都没发生。
`ENV` 选择同一目标底座使用的 env 文件，不创建隔离环境。
备份当前仅支持 `BACKUP_TARGET=local`；不再提供未实现的 Nexus 目标。
`RETENTION_DAYS` 为 0–99999 的整数，0 明确拒绝清理；正数只清理所选服务的
旧归档及清单，排除本次新包。默认停服备份，生成 `.tgz` / `.sha256` / `.meta`；
卷不存在或备份失败时 Job 失败，不生成“成功”的空备份。
恢复命令、范围限制与演练见 [备份与恢复](备份与恢复.md)。

脚本回归 `make test`（路由渲染 / LDIF 导入 / Job 定义）；共享库行为回归
`make test-groovy`（需要 groovy，缺失则自动跳过）。`make jobs-test` 只在本地渲染
XML、不连接 Jenkins，因此**不需要 .env**；真正推送用 `make jobs`。

## 验收（M0）

**2026-10-31 在 213（`10.22.67.213`，Docker 26.1.0 / Compose v2.26.1）真机逐条验过**，
不是「CI 绿了就算」。命令与实测结果见下面每条的括注。

- [x] `make deploy` 一条命令起 Jenkins + 权限 + 路由 + Caddy + Nexus
      （`USE_GHCR=1 make deploy` → rc=0，10 个服务全 healthy；**首次真机跑撞出 #29**，
      已修：`--build` 会撞 digest 引用）
- [x] 改 `config/routes.yaml` 后 Caddy 热加载新路由，旧路由不中断
      （追加 `tmpcheck` 路由 → 6 秒内 `200`，全程 `jenkins=302`/`nexus=200`；回滚后站点数回到 6。
      热加载由 `router` 容器的 watch 完成，**不是**从宿主跑 `make render` —— 宿主够不到 `caddy:2019`）
- [x] `curl --resolve jenkins.<domain>:443:<宿主IP> https://jenkins.<domain>/` 返回 302
      （实测 `302`）
- [ ] 局域网另一台机器（改 hosts 后）浏览器可完成 oauth2 登录并进入 Jenkins
      —— **需人工**，本轮只验到「未登录被拦 → 302 跳 auth」
- [x] `docker compose exec caddy getent hosts nexus.<domain>` 解析到 `172.31.0.10`
      （实测 `172.31.0.10`）
- [x] 旧路径入口 `http://localhost:8080/jenkins` 已不存在
      （`of-caddy` 只发布 `0.0.0.0:80`/`443`，直连 8080 连接被拒，curl 退出码 7）
- [ ] `deploy-service` 可按参数拉起指定服务
      —— **阻塞**：`make jobs` 推不进 Jenkins（宿主不解析域名 + API 被 oauth2 拦），见 #30。
      `make jobs-test`（离线渲染）正常，3 个 Job 都能生成
- [x] `backup-service` 产出可恢复的 `.tgz`
      （`bash scripts/backup.sh --service ldap` → 12K / 3 个文件；
      `restore.sh --dry-run` 打印恢复计划且 `State.StartedAt` 未变）
- [x] 未登录访问受保护站点被拦截（`jenkins.<domain>/` → 302 跳 `auth.<domain>`）
- [x] `https://home.<domain>/` 能打开并看到服务卡片
      （`200`，5 张卡，`{{HOMEPAGE_VAR_*}}` 已展开，链接指向 `jenkins.<domain>`）
- [x] bats 全绿（含 `18_public` / `19_dns` / `20_tls` / `21_homepage`）
      —— **CI 覆盖**（DinD 需要 `--privileged`，213 上没开，故未在真机跑）

**真机与 CI 的差距（这轮的主要收获）**：CI 全绿 + 文档写「已完成」+ 真机 `make deploy` 直接失败，
三者可以同时成立。原因见 #29 —— `deploy.sh` 这条路径 CI 完全不覆盖。
