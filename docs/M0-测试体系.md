# M0 测试体系

`make test` 保留原来的纯逻辑/静态检查（py_compile 仅检查 router，
不遍历 `tests/bats`）。`make test-bats` 增加真实服务断言：
bats 是 Bash 测试框架，直接复用 curl、jq、ldapsearch 和 Compose，
无需 Python 第三方依赖，退出码和 TAP 输出可直接接入 CI。

## 运行

```sh
make test-bats
# 调试：测试结束后保留内层 daemon、容器和数据，命令会继续等待
KEEP=1 make test-bats
# 另一个终端查看现场
docker exec -it orgflow-m0-test bash
# 调试结束停止 harness（不是宿主 orgflow-devops 栈）
docker stop orgflow-m0-test
# 再跑一次不带 KEEP 的测试，结束时清理内层栈和服务卷
make test-bats
```

要求宿主有 Docker、Compose、构建权限和 `--privileged` 权限。
测试镜像是 `orgflow/m0-test:24.04-v1`，基于 digest 锁定的 Ubuntu 24.04，
通过 Ubuntu apt 安装 docker.io、Compose v2、bats 等，不使用 Docker 官方下载站。
router/JJB/dnsmasq 同样基于该 Ubuntu 镜像，分别打 `orgflow/router:24.04-v1`、
`orgflow/jjb:24.04-v1`、`orgflow/dnsmasq:24.04-v1` 标签。Compose 的 build 默认名称
仅用于本地构建发现，不是远端浮动镜像来源。

宿主镜像缺失时，GHCR/Quay 可以按锁定 digest 拉取；Docker Hub 来源默认必须事先离线导入，
绝不依赖连接不可达的 Hub。无缓存的托管 CI 显式设置 `ALLOW_PULL_DOCKER_HUB=1`
才允许拉 Hub。router 与 dnsmasq 默认在每轮测试前按当前源码构建（复用构建缓存）。
`USE_GHCR=1 make test-bats` 改用全部 GHCR 锁定镜像（含 router/harness），
需先完成搬运和 `make images-pin`，详见 [镜像与 CI](M0-镜像与CI.md)。
内层 daemon 有独立 socket、网络和 `m0-dind` 数据卷，默认结束时 `compose down -v`，
保留镜像缓存。任何失败均输出诊断后返回非零；`KEEP=1` 在停止 harness 时返回原测试状态。

## 十一个用例

每文件一个 bats 用例（`14_caddy` 与 `20_tls` 各含多段），均不跟随 HTTP 重定向。
**所有 HTTP 断言都带域名与 SNI**：`curl -k --resolve <sub>.<domain>:8443:127.0.0.1
https://<sub>.<domain>/...`，测的是 Caddy 的站点匹配，不依赖 hosts 文件，
也不依赖某个固定端口。

| 文件 | 断言 |
|---|---|
| 00_stack | 7 个外部 image 全部匹配 lock、9 个默认服务、4 个自建 Dockerfile 同一 Ubuntu digest、9 个固定 IP 唯一 |
| 10_ldap | 管理员 bind、33 个条目、admin.zeek mail、users/groups/departments OU |
| 11_ldapadmin | `ldapadmin.<domain>/` 200、phpLDAPadmin 标识 |
| 12_dex | discovery 必需字段、issuer 等于 `https://dex.<domain>/dex`、非空 JWKS、healthz |
| 13_oauth2_proxy | `auth.<domain>/ping` OK、Jenkins 站点 302、跳转落到 `https://auth.<domain>/oauth2/start` 且带 `rd`、OIDC 参数 |
| 14_caddy | 5 个域名站点各自可达、Caddyfile 无路径式站点地址、80 端口只跳转、未知 Host 404、Nexus status |
| 15_router | 内部 healthz、渲染幂等、live mtime 不变、缺/非法/重复 subdomain 全部拒绝且不覆盖旧文件 |
| 16_jenkins | 内部 login 200、healthy、固定 IP 172.31.0.20、站点访问必须 302 |
| 17_nexus | UI 200、status 200（不检查空 body）、healthy、固定 IP 172.31.0.21 |
| 19_dns | dnsmasq 供货、容器内域名解析到 172.31.0.10、服务名仍可解析、9 个固定 IP 与架构图一致 |
| 20_tls | 每个站点签出对应域名证书、签发者为 Caddy 内部 CA、导出的根证书能校验整条链、不信任时握手必须失败 |

健康闸门最多等待 300 秒（Nexus 启动较慢）；之后在内层 LDAP 调用现有
`bootstrap-ldif.sh` 导入初始化数据，再执行断言。仓库里的 `.env` 只读复制到
`/tmp/m0.env` 后使用（不修改原文件）；不存在时从 `.env.example` 派生，
四个密码/secret 均随机生成，其中 cookie secret 为 32 个字符；
不会打印密钥或写回仓库。

## DinD 的取舍

1. **预灌镜像**：213 无法访问 Docker Hub。只读使用 `/host/docker.sock`，
   对 Compose 需要的镜像先检查宿主精确引用，再 `docker save | docker load`。
   classic Docker 的归档不保留 RepoDigest，因此将已验证的宿主引用映射成不可变
   image config ID，写入 `/tmp/m0-images.json` Compose override，并禁止 pull。
   内层显式使用 classic overlay2 image store，避免 Docker 29 默认 containerd
   store 将镜像 ID 解释成 manifest digest，与宿主 Docker 26 的 config ID 不一致。
   这不是用 tag 替代 digest 校验：实际运行的 ID 必须来自宿主对锁定引用的 inspect。
   未挂宿主 socket 时，所有精确引用必须已存在内层 daemon，否则明确报错，不跳过。
2. **固定域名与测试端口**：内层栈固定 `GATEWAY_DOMAIN=org-devops.com`，
   HTTPS 映射到宿主（harness 容器）`8443`、HTTP 映射到 `8080`，避免占 80/443。
   域名与端口以**追加**方式写进 env 文件（dotenv 后者生效），不受调用方 `.env` 影响。
   启动前先渲染 `out/Caddyfile` 与 `out/dex/config.yaml`：caddy 缺 Caddyfile 起不来，
   dex 是 scratch 镜像无法启动期渲染。
3. **Jenkins 走 exec**：它没有发布宿主端口。内部 login readiness 必须在容器内
   curl；网关的 302 只是认证要求，不能冒充 Jenkins 就绪。

`config`/`out` 是共享 bind mount，不要往其中写破坏性测试数据。
router 非法输入先对临时产物检查，确认拒绝后才验证 live 文件保持不变。
删除路由的反向验证会影响共享产物，必须保存并恢复配置，等 router 恢复
5 条路由并重新跑全绿；不能对宿主栈执行 down。

## 添加用例

在 `tests/bats` 新增编号 `.bats`，`setup()` 中
`load 'helpers/common'` 并调用 `setup_gw`。可用：

| 助手 | 用途 |
|---|---|
| `gw_code <sub> <path>` | 域名请求的状态码 |
| `gw_header <sub> <path> <Name>` | 取响应头 |
| `gw_body <sub> <path>` | 取 body（失败即非零） |
| `assert_gw <sub> <path> <code>` | 断言状态码 |
| `gw_wait <sub> <path> <code> <秒>` | 等待状态码 |
| `http_host_code` / `http_host_header` | 走 80 端口、用 `Host` 头指定域名 |
| `compose_exec` / `compose_cmd` | 容器内执行（自动带本轮 env 与镜像 override） |
| `assert_healthy` / `assert_fixed_ip` | 健康状态 / 固定 IP |
| `assert_resolves_in <服务> <域名> <IP>` | 容器内解析断言（getent/nslookup/dig 自动降级） |
| `assert_contains` | 子串断言 |

只断言外部行为，不打印环境或密码，不放宽确定的状态码/数量要求。
执行 `make test-bats` 验证，再故意破坏对应行为确认用例能失败——
例如把某服务的 `ipv4_address` 改错，`19_dns` 必须红；改回来必须绿。

## 升级镜像 digest（三步）

1. 从可信来源预先导入新镜像（外部可达 registry 可按精确 digest 拉取），
   确认本地 RepoDigest；若改 tag，先更新 lock 的引用列。
2. 执行 `make images-lock`，从本地匹配 repository 的实际 RepoDigest 原子重写
   `tests/images.lock`；同步 Compose image 和三个 Dockerfile 的 FROM/基座 label。
   lock 是单一真源，策略用例负责发现其他文件漂移。
3. 执行 `docker compose build router jjb dnsmasq`、`make jobs-test`、`make test`、
   `make test-bats` 后一起提交。Jenkins/Nexus 不再支持通过
   `JENKINS_VERSION`/`NEXUS_VERSION` 浮动升级；Job 的 `SERVICE_VERSION`
   只能与 lock 的 tag 一致，否则部署明确拒绝。
