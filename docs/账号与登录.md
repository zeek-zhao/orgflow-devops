## 2. 机器账号密码的统一存放：213 的 `.env`

所有**服务管理员密码**只存在一处——213 真机的 `~/workbuddy/orgflow-devops/.env`
（不入库，`.gitignore` 挡着）。查看（在 213 上，或 ssh 过去）：

```sh
ssh jenkins@10.22.67.213
cd ~/workbuddy/orgflow-devops
grep -E '^(JENKINS_ADMIN|NEXUS_ADMIN|LDAP_ADMIN)_(ID|PASSWORD)=' .env   # 按需看
```

| 变量 | 是谁的密码 | 谁用它 |
|---|---|---|
| `JENKINS_ADMIN_ID` / `JENKINS_ADMIN_PASSWORD` | Jenkins 本地管理员（`admin`） | 你登录 Jenkins UI；JJB 推 Job |
| `NEXUS_ADMIN_ID` / `NEXUS_ADMIN_PASSWORD` | Nexus 管理员（`admin`） | 你登录 Nexus UI；`nexus-deploy` 改密 |
| `LDAP_ADMIN_PASSWORD` | LDAP **目录管理员** `cn=admin,dc=devops,dc=com` | phpLDAPadmin 登录；bootstrap 导数据。**不是网页登录密码** |
| `OAUTH2_CLIENT_SECRET` | Dex ↔ oauth2-proxy 之间的机器凭据 | 服务互联，**人不用** |
| `GITHUB_TOKEN` | GitHub PAT（40 位） | Jenkins 共享库 checkout 本仓库 |

**改密码 = 改 `.env` + 让对应服务重读**：Jenkins/Nexus 改 `.env` 后重启对应容器或重跑
`nexus-deploy`（幂等）；LDAP 目录管理员密码改动要慎重（所有 bind 都用它）。
**任何情况下不要把 `.env` 内容贴进 issue / PR / 聊天记录。**

## 3. 人怎么登录（LDAP 账号，网关那道门）

**流程**（以 Jenkins 为例，ldapadmin 同理）：

1. 浏览器开 `https://jenkins.org-devops.com/` → 未登录自动 302 到
   `auth.org-devops.com/oauth2/start?rd=...`
2. 跳到 Dex 登录页 → 输 **LDAP uid + LDAP 密码**（例如 `svc-platform-admin`）
3. 认证通过跳回原站点，oauth2-proxy 种下 cookie——**之后所有走网关的站点一次通行**

**账号从哪来**：LDAP 里的用户，初始集在 [`services/auth/ldif/users.ldif`](../services/auth/ldif/users.ldif)
（`svc-platform-admin`、`svc-platform-dev`、`zeek.zhao`、`svc-platform-qa`、`svc-nexus-dev`、`svc-gerrit-dev` 等；
平台管理员是 `svc-platform-admin`，在 nexus/gerrit/jenkins/jira 四个 `*-admin` 组里）。
查某人是否存在：

```sh
ssh jenkins@10.22.67.213 'cd ~/workbuddy/orgflow-devops && \
  docker compose --env-file .env exec -T ldap ldapsearch -x -b dc=devops,dc=com "(uid=svc-platform-admin)" uid mail'
```

> ⚠️ **交付口径（#84）：全部 LDAP 初始账号的口令统一为 `123456`**（LDIF 内以
> `{SSHA}` 加盐哈希存放，明文不进 git）。这是占位口令——任何人首次登录后第一件事
> 就是改掉它（见 §4）。生产账号长期用占位口令 = 门没锁。

**怎么改自己的密码**：登录 `ldapadmin`（网关那道用旧密码过）→ 找到自己的条目
`uid=<你>,ou=users,dc=devops,dc=com` → 改 `userPassword` 属性 → 保存即生效
（Dex 下次登录用新密码）。

## 4. 每个服务的第二道登录

### Jenkins（网关过了以后）

Jenkins 自己还有登录页：用户 `admin`，密码 = `.env` 的 `JENKINS_ADMIN_PASSWORD`。
**这个 `admin` 是 Jenkins 本地账号，不在 LDAP 里**——网关账号和 Jenkins 账号是两套，
别拿 LDAP 密码去试 Jenkins 登录框。

### Nexus（没有网关这道门）

`https://nexus.org-devops.com/` UI 直接开（匿名只读浏览），点右上角 **Sign in**：
`admin` + `.env` 的 `NEXUS_ADMIN_PASSWORD`。REST API 同一套凭据
（`curl -u admin:*** https://nexus.org-devops.com/service/rest/v1/...`）。

### LDAP Admin（phpLDAPadmin）

网关过了以后是 phpLDAPadmin 自己的登录框，**Login DN 要写全**：

```
cn=admin,dc=devops,dc=com          ← 目录管理员，不是 uid
```

密码 = `.env` 的 `LDAP_ADMIN_PASSWORD`。只写 `admin` 会报登录失败——
这是它最常见的「登不进去」问题。

## 5. 密码忘了 / 登不进去，按这张表查

| 现象 | 真因多半是 | 怎么办 |
|---|---|---|
| Dex 登录页报「用户不存在」 | uid 拼错 / 用户没导入 | §3 的 ldapsearch 查一下 |
| Dex 登录页报凭据错误 | 密码不对（还是 123456？改过了？） | 让目录管理员在 ldapadmin 里重置 `userPassword` |
| 网关过了、Jenkins 登录框进不去 | 用了 LDAP 密码填 Jenkins 账号 | Jenkins 用 `.env` 里的 `admin` 那套（§4） |
| phpLDAPadmin 登录失败 | Login DN 没写全 | `cn=admin,dc=devops,dc=com` 全称（§4） |
| 页面根本打不开 / `000` | 不是账号问题：hosts 或证书 | [使用说明 §1](使用说明.md) 的两步前置 |
| 登录成功又弹回登录页（循环） | cookie 域 / 浏览器隐私模式 | 换普通窗口；清 `org-devops.com` 的 cookie 重试 |

## 6. GitHub（仓库本身）

| 在哪 | 用什么登录 |
|---|---|
| 网页 | GitHub 账号 `zeek-zhao`（本人） |
| 213 命令行 | `gh` 已登录（`gh auth status` 可查），git push/pull 走它的凭据 |
| Jenkins job | `.env` 的 `GITHUB_TOKEN`（40 位 PAT，共享库 checkout 用；**留空 job 会挂**，报错像网络问题但其实是它） |
| Windows 开发机 | `~/.config/wb/github.token`（同一枚 PAT 的本地副本） |

仓库是**私有**的：匿名访问一律 404（包括 CI 之外的 curl/截图工具），
不要转公开（内含内网 IP）。
