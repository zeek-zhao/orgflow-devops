# 架构总览

## 一句话

一台云主机上用 7 个独立 compose 工程起一套最小 DevOps 底座：DNS 解析 → 证书签发 → Caddy 唯一入口 → OpenLDAP 身份 → LDAP Admin → HomePage 面板 → 路由注册。Caddy 单入口按路径反代，Tailscale Funnel 在公网边缘终止 TLS；镜像全部 `digest` 锁定（4 薄封装 + 2 自建）。

## 组件表

| # | 组件 | 容器 | 职责 | 长驻 | 零依赖可起 |
|---|---|---|---|---|---|
| 1 | DNS | of-dnsmasq | `*.DOMAIN → .10` | 是 | 是 |
| 2 | 证书 | of-certs-init | 内部 CA + 站点证书 | 否(exit 0) | 是 |
| 3 | 入口 | of-caddy | 唯一入口，路径反代 + 内网 TLS 站点 | 是 | 是(bootstrap) |
| 4 | 身份 | of-ldap | OpenLDAP 目录 | 是 | 是 |
| 5 | 管理 | of-ldapadmin | LDAP Admin Web | 是 | 是(降级登录页) |
| 6 | 面板 | of-homepage | 占根 `/` 的统一面板 | 是 | 是(纯静态) |
| 7 | 路由 | of-router | `routes.yaml→reload` | 是 | 是(503 降级) |

> 编排：无顶层 compose。`up.sh` 按 `services/manifest.tsv` 的 `order` 逐服务 `-p orgflow-<svc> -f services/<svc>/compose.yml` 拉起；网络与卷为 external（真实名带 `orgflow-minimal_` 前缀）。

## 拓扑

```
公网 / Tailnet
    │  TLS（Funnel 边缘终止，合法 *.ts.net 证书）
    ▼  :PUBLIC_PORT(18081) 明文回源
Caddy（唯一入口，192.168.90.10；admin 只绑内网 :2019）
    ├─ /           → homepage:3000   (.11)   HomePage 占根，/_next /api 随根命中
    ├─ /ldapadmin/ → ldapadmin:80    (.12)   strip 前缀
    ├─ /router/    → router:8080     (.14)   strip 前缀
    ├─ /healthz /status → 探针 respond 200
    └─ 无公网 /caddy/*（admin 公网不可达，P0）

内网 TLS 站点（:443，证书由 certs-init 签发，SAN 含 *.$DOMAIN）：
    home.$DOMAIN / ldapadmin.$DOMAIN / router.$DOMAIN → 各自后端

内网 docker 网桥 orgflow-minimal_orgflow（192.168.90.0/24）：
    dnsmasq .15(53/udp)   ldap .13(389)   certs-init 一次性
```

## 固定 IP 与端口

| 服务 | 固定 IP | 内部端口 | 隔离端口 |
|---|---|---|---|
| caddy | .10 | 80/443/2019 | 8080/8443 |
| homepage | .11 | 3000 | 8082 |
| ldapadmin | .12 | 80 | 8081 |
| ldap | .13 | 389 | 3389 |
| router | .14 | 8080 | 8083 |
| dnsmasq | .15 | 53/udp | 5353 |
| certs-init | 动态 | — | — |

| 端口 | 服务 | 暴露范围 |
|---|---|---|
| 80/443 | caddy | 宿主（内网唯一入口） |
| 2019 | caddy admin | 内网固定 IP（公网不可达） |
| 18081 | caddy 公网 path 入口 | Funnel 转发 |
| 各隔离端口 | 单服务 | 宿主（单服务启动用） |

## 启动顺序与就绪判据

1. dnsmasq（无前置）→ dig 返回 .10
2. certs-init（无前置）→ exit 0 且卷内有 CA + 证书
3. ldap（无前置）→ ldapsearch 成功
4. caddy（前置 certs-init）→ Admin API 200；未就绪报 **D003** 并中止
5. homepage（前置 caddy）→ :3000 可连
6. ldapadmin（前置 ldap,caddy）→ :8080 可连
7. router（前置 caddy,homepage,ldapadmin）→ /healthz 200

## 降级策略（缺邻居不崩）

- caddy 无证书 → 生成 bootstrap 自签占位
- ldapadmin 连不上 ldap → 显示登录页并重试
- router 连不上 caddy → `/render` 返回 503 而非 exit

## 证书设计

- CA 10 年 / 站点 825 天，`make ca-rotate` 轮换
- SAN 覆盖 `*.$DOMAIN` + 各子域 + apex
- `make ca` 导出根证书，客户端手工安装
- 幂等：已存在且未过期跳过，`FORCE=1` 才重签
- 默认 internal + Funnel；acme 为可选生产模式（需公网域名 + 80/443），见[证书与CA](engineering/证书与CA.md)

## 分层排查决策树

1. **公网进不来** → `tailscale funnel status` / 安全组 → 查 Caddy `:PUBLIC_PORT` handle。
2. **域名不解析** → `dig @127.0.0.1 -p 5353 home.DOMAIN` → 查 dnsmasq `address=/.DOMAIN/` 指向的 `GATEWAY_IP`。
3. **站点 502** → `curl :2019/config/` 看 upstream 是否指向正确服务名（homepage 不是 home）→ 查后端容器是否 healthy。
4. **证书告警** → internal 模式需装根证书（见证书与CA.md）；acme 模式查 80/443 可达。
5. **容器 unhealthy** → `bash status.sh` → `docker logs of-<svc>` → 对照服务手册故障排查段。
