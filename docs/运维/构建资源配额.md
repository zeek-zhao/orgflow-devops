# 构建资源配额（M2.5 P0 / m2.5.1 生命周期加固）

## 1. 铁律（对实施/构建 Agent 的强制约束）

每次启动构建容器前必须记录四项，缺一项即 BLOCKED，不得继续构建、不得写成 `full-quota PASS`、不得回写 Verified：

1. `nproc`
2. `/proc/meminfo` 的 `MemTotal`（kB）
3. `docker info --format 'NCPU={{.NCPU}} MemTotal={{.MemTotal}}'`
4. `docker inspect <容器> --format 'NanoCpus={{.HostConfig.NanoCpus}} Memory={{.HostConfig.Memory}} CpuQuota={{.HostConfig.CpuQuota}}'`

四项必须显示宿主全部资源，且目标容器 `NanoCpus=0`、`Memory=0`、`CpuQuota=0`。

### 判据（脚本内置）

| # | 断言 | 说明 |
|---|---|---|
| 1 | `docker info` 的 `NCPU == nproc` | 精确相等，不是"接近" |
| 2 | `docker info` 的 `MemTotal == /proc/meminfo MemTotal(kB)×1024` | 允许 ≤1% 测量偏差，偏差值必须打印；超过 BLOCKED |
| 3 | `docker inspect NanoCpus=0` | 精确 0 |
| 4 | `docker inspect Memory=0` | 精确 0 |
| 5 | `docker inspect CpuQuota=0` | 精确 0 |
| 6 | 四项落盘成证据文件 | 无文件 = BLOCKED，不接受"日志里有" |
| 7 | 启动前后宿主三项一致（P2-1） | `--preflight` 快照与启动后采集比对，不一致 BLOCKED |

**新鲜度（≤10 分钟）属消费端职责**：脚本只写 `ts`，不自判新鲜度（m2.5.1 P1-2 删除了半成品 `--max-age-min`）。判新鲜度在 `build-from-gerrit` 的 Quota gate（严格 FAIL）与 `verify-quota-guard`（WARN 提示）两处完成。

**禁止项**：任一缺失/命令失败/容器不存在/启动前后宿主变化/数值不匹配 → verdict 只能是 `BLOCKED`；不得写 `PASS` 或 `full-quota PASS`，不得继续 `buildctl build`，不得回写 Verified。

## 2. 脚本用法

```bash
# 完整取证（默认，门禁消费）
bash scripts/quota-guard.sh --container of-builder --out artifacts/quota
# 启动前宿主预检（只查宿主三项，docker 被限权即 BLOCKED）
bash scripts/quota-guard.sh --container of-builder --out artifacts/quota --preflight
# 启动后取证并与预检快照比对
bash scripts/quota-guard.sh --container of-builder --out artifacts/quota --compare-preflight artifacts/quota/host-preflight.json
# 退出码：0=PASS  2=BLOCKED(缺项/不匹配)  3=环境不可用(docker 不可达/容器不存在)
```

stdout 固定四行（便于 CI 日志 grep，`--preflight` 只打前三行）：

```
[quota] nproc=5
[quota] MemTotal=8570968 kB
[quota] docker info NCPU=5 MemTotal=8776671232
[quota] inspect NanoCpus=0 Memory=0 CpuQuota=0
[quota] verdict=PASS reason=none
```

### 证据文件（m2.5.1 P1-1：按容器名隔离）

| 文件 | 用途 | 是否参与门禁 |
|---|---|---|
| `latest-of-builder.json` | **门禁消费端固定读此文件** | ✅ 是 |
| `latest.json` | 最后写入者的人类查看副本 | ❌ 否 |
| `<UTC>-<container>.json` | 历史快照，用于审计 | ❌ 否 |
| `host-preflight.json` | 启动前宿主三项快照，供比对 | ❌ 否 |
| `alive.json`（m2.5.3 P0-2） | 宿主 loop 自证存活：pid + `ps -p PID -o args=` + mechanism + ts + log_last_ts | ✅ 是（verify-quota-refresh） |
| `mechanism.txt`（m2.5.3） | 安装目标写入的刷新机制声明（systemd-timer/cron/supervisor/runit/nohup） | ❌ 否（quota-status 展示） |
| `cron.log` / `supervisor.log` | 刷新日志（>1MB 自轮转为 `.1`） | ✅ 是（日志新鲜度判据） |

证据 JSON 的 `result` 字段（m2.5.3 P2-2）为总体结论（PASS/FAIL/WARN），与 `verdict` 同一口径：`verdict=PASS → result=PASS`，`BLOCKED → FAIL`。机器消费者读 `latest.json | jq .result` 即得结论，不再得到 null。

按容器名隔离后，单服务重建 `up.sh --only jenkins-agent` 只会写 `latest-of-jenkins-agent.json`，**不会覆盖 `latest-of-builder.json`**，Quota gate 仍可 PASS——不再需要"记得重跑一次 builder"。

`make quota-guard` 是等价入口（需 docker）；`bash scripts/quota-status.sh` / `make quota-status` 查看证据 ts/age/result + 当前 mechanism。

## 3. 三处接入点（缺一处等于没做）

1. **up.sh（P2-1 两段式）**：`builder` / `jenkins-agent` 启动**前**先跑 `--preflight` 采集宿主三项并校验 docker 未被限权，任一项不满足 → 立即 BLOCKED 非 0 退出，绝不带病启动容器；`compose up` 成功后再跑 `--compare-preflight` 完整取证并与前置快照比对，落 `latest-of-builder.json`；任一项不满足 → BLOCKED 非 0 中止，不再启动后续服务。
2. **build-from-gerrit Pipeline**：`Checkout change` 之前新增 `stage('Quota gate')`，只读 `/opt/orgflow/quota/latest-of-builder.json`（repo 的 `artifacts/quota` 只读挂进 controller 与 agent），断言 `verdict==PASS`、`container==of-builder`、`ts` 距今 ≤10 分钟、三项配额原值为 0；不满足 → `BUILD BLOCKED`，构建立即失败，不进入 checkout/build/回写。
3. **只读挂载**：`artifacts/quota` 以 bind mount 只读挂到 controller 与 agent 的 `/opt/orgflow/quota:ro`。构建前只消费证据，**不给 agent 挂 docker.sock**——任何"给 agent 挂 docker.sock 检查配额"的做法一律否决（M1 安全基线）。

## 4. 证据生命周期与自动刷新（m2.5.1 P0-1 / m2.5.2 双路径 / m2.5.3 服务化 / m2.5.4 单实例）

- **生命周期 10 分钟**：Quota gate 要求证据 `age ≤ 10min`。证据一旦超过 10 分钟，推任何 change 都会在 Quota gate 被 BLOCKED（自锁）。**自动刷新是硬要求**——靠手动 `make quota-guard` 不可靠（休眠/遗忘即 stale）。
- **自动刷新机制（m2.5.3 服务化）**，按 PID1 选，优先级从高到低：
  1. **systemd timer（主路径）**：`deploy/systemd/orgflow-quota.service` + `orgflow-quota.timer`（`OnBootSec=2min`、`OnUnitActiveSec=5min`、`Persistent=true`），`make quota-install`。适用 PID1=systemd。
  2. **cron**：`make quota-cron-install`。用户 crontab 用 5 字段模板 `deploy/cron/orgflow-quota.cron`；`/etc/cron.d` 用 6 字段模板 `deploy/cron/orgflow-quota.cron.d`（第 6 字段 root）。**两者不可混用**，安装后 `awk 'NF>=6 && $1!="#"'` 校验。适用 cron daemon 可用的部署。
  3. **supervisor / runit（进程守护，m2.5.3 新增）**：PID1=supervisord 用 `make quota-supervisor-install` 注册 `[program:orgflow-quota]`（autostart/autorestart=true）；其他 PID1 用 `make quota-runit-install` 软链 `/etc/sv/orgflow-quota` + `sv up`。无 `supervisorctl` CLI 但有 socket 时用 `SUPERVISOR_SOCKET=/path/to.sock python3 scripts/supervisor-rpc.py <action>` 走 XML-RPC（socket **必填**，真机优先 supervisorctl）。
     - **watchdog 条件启用（m2.5.4 P0-1，防双实例）**：`[program:orgflow-quota-watchdog]` 默认 `autostart=false`。真机 supervisor 原生 `autorestart=true` 足以拉起 loop，**watchdog 必须关**——否则在"supervisor 杀旧进程到拉起新进程"的间隙 watchdog 会再 nohup 一个 loop，形成双实例双写。仅当本机 autorestart 实测失效（本沙箱云 IDE）才 `make quota-supervisor-install WATCHDOG=1` 打开。watchdog 拉起前还会做全局实例判断（`count_instances`），已有 loop 就不拉起。
     - **安装可移植性（m2.5.4 P1-1）**：conf 目录由 `scripts/supervisor-conf-dir.sh` 严格探测（显式 `SUPERVISOR_CONF_DIR` → supervisorctl 默认 `/etc/supervisor/conf.d` → 读 supervisord.conf include → 报错 exit 2），**绝不静默落到沙箱的 `/usr/local/share/supervisor`**。装后必须断言服务真的 RUNNING（supervisorctl 或 rpc state），非 RUNNING → exit 2。
  4. **nohup daemon（最后兜底）**：`make quota-daemon-install`（常驻循环）。**仅当以上均不可用时才用**，且必须在执行日志写明理由（本沙箱即此情形：PID1=supervisord 无 supervisorctl CLI、cron daemon 不扫描 `/etc/cron.d`）。
- **统一循环脚本**：三种管理器与 nohup 都调用 `scripts/quota-guard-loop.sh`，每 300s 刷新一次；内置日志自轮转（`cron.log` >1MB 即 mv `cron.log.1`，保留 1 份；真机可选 `deploy/logrotate/orgflow-quota` 二选一）；每次刷新写 `artifacts/quota/alive.json`（pid + `ps -p PID -o args=` 命令行 + mechanism + ts + log_last_ts + **m2.5.4 新增 `instances`/`pidfile_pid`**），供 agent 只读判活。刷新命令不再散落在 Makefile。
  - **单实例保证（m2.5.4 P0-1/P0-2）**：EXIT trap 只删"自己的" pidfile（比对内容 == 自身 PID），旧 loop 晚退出不会误删新 loop 的 pidfile；`alive.instances` 用 `/proc` 精确统计全场 loop 实例数，`verify-quota-refresh` 判据要求 `instances==1 && pidfile_pid==pid`，双实例立即 FAILURE 并打印 ps 列表。报告 `guard-quota-alive` 行 evidence 含 `instances=1`。
- **装服务前清理**：`make quota-cleanup-nohup` 按 daemon.pid 且核对命令行含 `quota-guard-loop.sh` 精确停旧进程，绝不 `pkill -f quota-guard` 误杀手动调用；禁止两个刷新器并行写同一 `latest-of-builder.json`。
- 所有路径都**只由宿主侧写证据，容器只读挂载**；不给 jenkins-agent 挂 docker.sock；服务化后的 loop 同样如此。

- **如何判断哪条在生效（部署机执行并原样记录）**：
  ```bash
  ps -p 1 -o comm=                                          # systemd / supervisord / 其他
  ls -d /run/systemd/system 2>/dev/null && echo systemd-ok || echo systemd-absent
  systemctl list-timers --all 2>/dev/null | grep -i orgflow-quota || echo no-timer
  crontab -l 2>/dev/null | grep quota || grep quota /etc/cron.d/orgflow-quota 2>/dev/null || echo no-cron
  SUPERVISOR_SOCKET=/path/to/cs-supervisor.sock python3 scripts/supervisor-rpc.py status orgflow-quota 2>/dev/null || echo no-supervisor-rpc  # socket 必填
  cat artifacts/quota/daemon.pid 2>/dev/null | xargs -r ps -p    # loop 兜底时在跑
  make quota-status                                         # 直接打印 mechanism=... + ts/age/result
  ```
  `make quota-status` 输出 `mechanism=systemd-timer|cron|supervisor|runit|nohup|none`，声明（`mechanism.txt`）与进程实际状态不一致时给 ⚠ 提示（以实际进程为准）。
- **自愈验收**：`kill -9 $(cat artifacts/quota/daemon.pid)` 后 ≤60s 应**只拉起 1 个**新 PID（`alive.instances==1`，`pgrep -fc` 验证），新 PID 与 `make quota-status` 的 mechanism 一致；`verify-quota-refresh` Job 校验「进程命令行匹配 + instances==1 + 日志新鲜≤8min + 证据 age≤10min」防假绿（双实例会判红）。反证：人为再起一个 loop → verify FAILURE（instances=2）→ 清理后恢复 SUCCESS。

- **部署后先确认再推代码**：部署顺序固定为 **`git pull` → `make check` → `up.sh --recreate/--pull` → 安装刷新机制（quota-install/cron-install/supervisor-install/runit-install/daemon-install 择一）→ `make quota-status` 确认为 0 → 再推代码**；自检报告 `commit` 必须等于当前部署头（未先 pull 就 reload 会让报告 commit 落后一版）。详见 [升级与回滚](升级与回滚.md)。

## 5. 为什么不让 Agent 直接跑 docker

`orgflow-agent` 按设计不带 `docker.sock`。配额证据必须由宿主侧（有 docker 权限的 `up.sh` / `quota-guard.sh`）采集并落盘，agent 只读消费。这样构建容器无法自我放宽配额、也不扩大攻击面。

## 6. 反证记录（2026-11-27 实测）

| 场景 | 期望 | 实测 |
|---|---|---|
| 正常态 `of-builder`（配额全 0） | PASS，exit 0，四行原值 + 证据文件 | PASS，exit 0 ✓ |
| 容器不存在 | BLOCKED，exit 3，reason 写明缺失项 | exit 3 ✓ |
| `docker create --cpus 2` 临时容器 | BLOCKED，exit 2，`NanoCpus=2000000000` | exit 2 ✓ |
| 篡改证据 `ts` 为 1 小时前 | Quota gate `stale=61min` → BLOCKED | BLOCKED ✓ |
| 删证据文件 | Quota gate `evidence missing` → BLOCKED | BLOCKED ✓ |
| 启动前后宿主 nproc 变化（篡改 preflight） | BLOCKED `启动前后nproc变化(999→5)` | BLOCKED ✓ |
| `up.sh --only jenkins-agent` 后 | `latest-of-builder.json` 不变，Quota gate 仍 PASS | PASS ✓ |
| 恢复配额/证据后重跑 | PASS，推 change 可正常 SUCCESS | PASS ✓ |

BLOCKED 日志中不得出现 `full-quota PASS` 字样（已用 `grep -rn 'full-quota PASS' logs/` 核验）。
