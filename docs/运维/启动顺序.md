# 启动顺序（DOC-03）

> 状态：适用 | 最后核对：2026-11-25 | 对应分支：feat/m1-jenkins


## 顺序表（v1.0 §5）

| 步 | 服务 | 依赖 | 就绪判据 |
|---|---|---|---|
| 1 | dnsmasq | 无 | `dig @127.0.0.1 -p 5353 home.DOMAIN` 返回 caddy IP |
| 2 | certs-init | 无 | 退出码 0，ca/ 内有 CA 与站点证书 |
| 3 | ldap | 无 | 匿名被拒 + 管理员绑定成功 |
| 4 | caddy | certs-init | admin API `/config/` 200 |
| 5 | homepage | caddy | :3000 可连 |
| 6 | ldapadmin | ldap, caddy | :8080 可连 |
| 7 | router | caddy, homepage, ldapadmin | /healthz 200 且 reload ok |
| 8 | jenkins | ldap, dnsmasq | logs 见 "Jenkins is fully up and running"；`/jenkins/login` 200 |
| 9 | jenkins-agent | jenkins | `/computer/api/json` 里 `orgflow-agent` offline=false |

> M1 顺序关键点：必须等第 8 步 controller 出现 `Jenkins is fully up and running` 后再起第 9 步 agent，否则 agent 会因 controller 未就绪反复重连。per-service compose 不能跨文件 `depends_on`，顺序由 manifest 的 `depends_on` 列 + `up.sh` 保证。

## 执行

```bash
make up                 # up.sh：就绪断言、失败即停、五段输出
DRY_RUN=1 bash up.sh    # 只演不跑（AC-16）
bash up.sh --from caddy # 断点续（前面已健康 skip）
bash up.sh ldap         # 单服务（缺依赖跳过继续）
JSON=1 bash up.sh       # 机读每步结构体
```

## 失败现象与处置

| 失败步 | 现象 | 处置 |
|---|---|---|
| certs-init | 容器 exit 1 | 查 `docker logs of-certs-init`；CA 目录写权限 |
| caddy | admin 2019 不通 | 查 2019 端口占用；Caddyfile 语法 `caddy validate` |
| ldap | unhealthy | osixia 首启 chown LDIF：确认 `--copy-service` |
| ldapadmin | 302 循环 unhealthy | 健康探针 `follow_location=0`，compose `$$` 转义 |
| router | /render 422 | routes.yaml upstream 非法（应 service:port） |
| jenkins | 一直 starting / 8080 不 ready | JCasC 写错（LDAP 连不上、fileOnMaster 私钥）；查 `docker logs of-jenkins`，用上一版 `jenkins.yaml.bak` 回退，勿开 ignoreInvalid |
| jenkins-agent | 节点离线 / 反复重连 | controller 未 fully up 就起了 agent；或 host key 变了（须用 secrets/agent_host_key 固定 + manuallyProvided） |

## 失败即停（AC-17）

任一步未通过就绪断言 → 打印「失败于 X；后续 N 步未执行」→ 退出码 1，不继续后续步骤。
