# 路由注册（DOC-05）

> 状态：适用 | 最后核对：2026-11-24 | 对应分支：feat/m0-v2

## 单一真源原则（T6）

路由只有**两份源文件**，二者由 router 合成后下发 Caddy，合成结果 == 实跑配置，**不存在第二份配置**：

| 源文件 | 职责 | 是否含动态路由 |
|---|---|---|
| `config/Caddyfile` | 启动挂载骨架：admin 内网绑定 + `:80` 跳转 + `:PUBLIC_PORT` 公网路径块（含 `/healthz`、`/status`、4 条 308、`@render` 403、反代 handle） | 否（骨架） |
| `config/routes.yaml` | 动态路径前缀 → upstream 片段 | 是（唯一路由真源） |

`services/router/server.py` 的 `render()` 读取 `routes.yaml`，与 Caddyfile 公网骨架合成**完整自洽的 Caddyfile**，经 Caddy admin `/load` 下发。下发的就是 render 原文，因此「渲染输出 == Caddy 实跑配置」。

> **已删除**：`home.{$DOMAIN}` / `ldapadmin.{$DOMAIN}` / `router.{$DOMAIN}` 三个子域 vhost 与 `tls /ca/...` 站点证书块。对外统一走**单域名路径型**，TLS 在 Tailscale Funnel 边缘终止。`scripts/check-domain.sh` 有门禁断言，Caddyfile 再出现 `<label>.{$DOMAIN}` 子域站点即失败。

## routes.yaml 字段

```yaml
routes:
  - prefix: /             # 根路径：homepage 占根，直接反代不 strip
    upstream: homepage:3000
  - prefix: /ldapadmin    # handle_path /ldapadmin/*，strip 前缀后反代 ldapadmin:80
    upstream: ldapadmin:80
  - prefix: /router       # handle_path /router/*，strip 前缀后反代 router:8080
    upstream: router:8080
```

- `prefix`：以 `/` 开头的路径前缀；根 `/` 特殊处理（直接反代不 strip），其余渲染为 `handle_path <prefix>/*`。
- `upstream`：必须 `service:port` 格式（compose 服务名 + 端口），否则 422 拒绝 reload。
- 兼容旧字段 `host`（归一为 `/<host>`），但新配置一律用 `prefix`。

## 公网固定片段（render 与 Caddyfile 同源）

`render()` 的 `PUBLIC_FIXED` / `STATUS_HTML` 与 `config/Caddyfile` 公网块内容一致：

- `/healthz` → 纯文本 `ok`（探活用，不改 HTML）。
- `/status` → HTML 状态说明页（7 服务入口与探测方式）。
- 4 条 308：`/home`、`/home/*` → `/`；`/ldapadmin` → `/ldapadmin/`；`/router` → `/router/healthz`；`/caddy`、`/caddy/*` → `/status`。
- `@render path /router/render` → `respond 403`（公网禁止触发渲染，必须先于 `/router/*`）。

## 渲染流程

1. 改 `config/routes.yaml`（动态路由真源）。
2. `make routes`（= `scripts/render-routes.sh`）→ 容器内执行 `docker exec of-router python3 /app/server.py --render`。
3. router：读 routes.yaml → 校验 prefix/upstream → 合成完整 Caddyfile → 以 `text/caddyfile` POST Caddy admin `/load` → Caddy 内置 adapter validate。
4. 30 秒内新前缀 200；配置 hash 与上次相同则幂等跳过 reload。
5. 容器无 curl，宿主机 `POST /render` 会被 403 拒绝；正式入口是容器内 CLI `--render` / 容器内本机回环 POST。

## 热更新端点

| 端点 | 方法 | 来源 | 说明 |
|---|---|---|---|
| /healthz | GET | 任意 | 存活 → `ok` |
| /routes | GET | 任意 | 当前渲染配置的**脱敏**展示（去内网 admin IP 与 `/ca/` 证书路径）；下发实跑配置不脱敏 |
| /render | POST | **仅容器内本机**（127.0.0.1 / ::1） | 校验+渲染+reload；公网 Caddy `@render` 403 兜底；坏 prefix/upstream 或 validate 失败 → 422；Caddy 不可达 → 503；非本机 → 403 |
| CLI `--render` | — | 容器内 | `python3 /app/server.py --render`，容器无 curl 时的正式入口 |

## reload 失败排查

- 403（公网 POST /render）：符合预期，公网禁止触发；改用容器内 `--render`。
- 422：routes.yaml 有非法 prefix/upstream 或 Caddy validate 失败 → 看响应体错误说明。
- 503：Caddy admin（192.168.90.10:2019）不可达，配置未加载 → 查 caddy 容器。
- 200 但路径不通：查 `routes.yaml` 前缀拼写、upstream 服务名/端口、Caddy `/config/` 当前配置是否为 render 原文。
