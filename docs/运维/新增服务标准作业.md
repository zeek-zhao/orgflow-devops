# 新增服务标准作业（SOP）

> 适用：向 orgflow-devops 底座新增一个容器化服务（如 M2 的 gerrit / cgit / harbor）。
> 目标：任何新增服务都能被 `make check` / `make check-all` 门禁覆盖，且 `make up` 一条命令可复现。
> 纪律：**只生成骨架，真源人工改**——单一真源原则见下，脚本绝不自动改 manifest/images.lock/docs。

## 0. 单一真源清单（改哪个文件由这里决定）

| 真源 | 作用 | 谁改 |
|---|---|---|
| `services/manifest.tsv` | 服务编排唯一真源（order/depends_on/public_path/监控元数据） | 人工 |
| `config/defaults.env` | IP / 对外端口 / 非敏感默认值 | 人工 |
| `config/images.env` | 镜像 tag 与上游 digest 登记 | 人工 |
| `tests/images.lock` | 镜像内容哈希门禁（自建 HASHED / 官方 digest） | 人工 |
| `config/routes.yaml` | 公网路径路由前缀（`make routes` 合成 Caddyfile） | 人工 |
| `docs/services/<name>.md` + `docs/README.md` | 服务手册与索引（双向一致） | 人工 |

脚本生成的骨架（可覆盖）：`services/<name>/{compose.yml,Dockerfile,README.md}`。

## 1. 生成骨架

```bash
bash scripts/new-service.sh <name>        # name 须小写字母/数字/连字符，字母开头
# 生成 services/<name>/{compose.yml,Dockerfile,README.md}，拒绝覆盖已存在目录
```

随后按 new-service.sh 打印的 5 步清单继续（下面展开为完整流程）。

## 2. 登记编排（manifest）

在 `services/manifest.tsv` 按 `order` 插入一行，9 列对齐（表头见文件首行）：

```
order  service  depends_on  health_url_doc  monitor_url_doc  ping_url_doc  public_path  tags  ui_kind
```

- `order`：启动顺序号；`depends_on`：逗号分隔依赖服务（up.sh 据此拓扑排序）。
- `public_path`：真实公网路径前缀；**无公网 UI 的服务写 `/none`**（渲染脚本已避免生成死链）。
- 三个 `*_url_doc` 是文档元数据，脚本不消费，但要填真实内网地址便于排障。

## 3. 网络与端口（defaults.env）

```
IP_<NAME>=192.168.90.x        # 固定内网 IP（网格 192.168.90.0/24）
P_<NAME>_HTTP=<port>          # 对外回环口，禁写死对外字面端口
```

命名规则：服务名小写转大写、连字符转下划线（`new-service.sh` 结尾会打印确切变量名）。

## 4. 镜像与供应链

**自建镜像**（有 Dockerfile，如 cgit）：
1. 写 `Dockerfile`（FROM 必须用已登记 digest，见 `config/images.env` 的 `UPSTREAM_*`）。
2. `bash scripts/image-hash.sh <name>` 算内容哈希，取前 12 位。
3. `config/images.env` 写 `IMAGE_<NAME>=...:ctx-<12位>`；`tests/images.lock` 写同 tag + hash。
4. 两个 compose（真实部署 + 测试）的 image tag 同步为 `ctx-<12位>`。

**官方镜像**（如 gerrit）：
1. 海外 runner 在 `.github/workflows/mirror-m2.yml` 加 pull/push 步骤，中转推 GHCR。
2. `config/images.env` 登记上游真实 manifest digest（`UPSTREAM_*`），**不使用代理重签的 digest**。
3. `tests/images.lock` 写同 digest；compose 默认走 GHCR tag，国内用 `GHCR_PROXY` 覆盖。

门禁：`make images-guard`（tag/hash 漂移即拒绝部署）、`make images-upstream`（FROM 与登记一致）。

## 5. 路由与入口（routes.yaml）

- 公网路径型服务：在 `config/routes.yaml` 加路径前缀，`make routes` 合成 Caddyfile。
- **Caddy 占位符语法是 `{$VAR:default}`，不是 compose 的 `${VAR:-default}`**（踩坑记录）。
- 独立端口服务（如 gerrit :8443）：在 Caddyfile 单开 `:{$PUB_HTTP_<NAME>:<port>}` 块。
- Tailscale Funnel 端口映射表在 `scripts/funnel-up.sh`，新增对外端口须加入对账表。

## 6. 部署脚本与健康检查

- `services/<name>/compose.yml`：固定 IP、network `orgflow`、label `org.of.fp`、healthcheck。
- healthcheck 命令只能用镜像内确定存在的工具：镜像若无 curl/wget，用 `bash -c 'echo > /dev/tcp/127.0.0.1/<port>'`（见 cgit）。
- 口令等敏感值：用 entrypoint 从环境变量渲染到卷内配置（600/属主），**不入库、不进文档、不经 git**；渲染用 python3 `str.replace` 字面替换，不用 sed（口令含 `|&` 会破坏）。

## 7. 文档与索引

- 新建 `docs/services/<name>.md`：镜像来源、端口、卷、初始化、已知约束、验收判据表（标注已验证/待办，不虚报）。
- 在 `docs/README.md` 登记链接，保持双向一致（`scripts/check-docs.sh` 会校验）。
- 若涉及安全策略偏离（如匿名可读），写进服务手册说明为既定策略，而非留作"缺陷"。

## 8. 测试用例

- 新增 `tests/features/S-<name>.feature`（格式参照现有 S-*.feature）：Given/When/Then 写可复现判据。
- 需独立命名空间的集成测试放 `tests/bats/`，用 `make e2e` 在 ofv2 命名空间跑，线上零影响。
- CI 门禁：`make check`（快检）+ `make check-all`（含镜像）+ `make test`（静态语法）。

## 9. Jenkins 集成（可选）

- 新服务健康探活 Job：`config/jenkins/jobs/verify-<name>.groovy` + `ci/jenkins/pipelines/verify-<name>.Jenkinsfile`（参照 verify-jenkins-agent）。
- 提交触发评审流需 gerrit-trigger / HTTP password，属管理员凭证初始化项，单列不混入门禁。

## 10. 验收清单（提交前逐条打勾）

- [ ] `make render && make check && make check-all && make test` 全绿
- [ ] `bash scripts/render-homepage.py --check` 通过，无 `/none` 死链、无重复入口
- [ ] 容器 healthy，公网入口 200
- [ ] 敏感值无明文入库（`secret-scan.sh`）
- [ ] 服务手册与 `docs/README.md` 双向登记
- [ ] 执行日志记录本次新增（`docs/records/执行日志/`）
- [ ] 一功能一提交，commit message 说明真源变更

## 附：踩坑速查

| 现象 | 根因 | 修复 |
|---|---|---|
| 配置占位符没渲染 | Caddyfile 用了 `${VAR:-def}` | 改 `{$VAR:default}` |
| 口令渲染后配置损坏 | `sed s\|...\|` 遇 `\|`/`&` | python3 `str.replace` |
| Gerrit LDAP 登录失败 | 用了 `bindDN/bindCredential`（无效键） | 用 `username/password` + `supportAnonymous=false` |
| cgit 公开了 All-Users | `scan-path` 扫全目录 | 改 `project-root` + `project-list` 白名单 |
| 主页 /none 死链 | 状态卡直接用 public_href | 状态卡 href 统一落 /status |
