# 自检框架（M2.4 Phase3）

> 状态：适用 | 最后核对：2026-11-27（m2.5.5） | 分支 `feat/m2-gerrit-cgit-harbor`
> 面向运维：如何跑自检、看报告、加检查项。面向写代码的人的手册见 [Gerrit 人工使用指南](../使用手册/Gerrit-人工使用指南.md)。

## 1. 它是什么

一条 Jenkins 编排 Job `selfcheck`（跑在 controller，`agent none`，只用 `build` 步骤调子 Job），按清单 `ci/selfcheck/checks.tsv` 逐条触发子 Job，汇总结果生成**自包含** HTML + JSON 报告，经共享卷由 Caddy 在公网发布到 `/reports/selfcheck/`。

- 清单真源：`ci/selfcheck/checks.tsv`（7 列：`id/kind/target/title/what/expect/timeout`）。
- 门禁：`scripts/check-selfcheck.sh`（接入 `make check`），保证清单与 Job 双向一致。
- 报告：`selfcheck-<build>.html/json` + `latest.html/json`，目录 `/reports/selfcheck`（Jenkins rw）/ `/srv/reports`（Caddy ro）。

## 2. 跑自检

Jenkins → `selfcheck` → `Build with Parameters`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `INCLUDE` | 空 | 逗号分隔 id；留空 = 全部 |
| `EXCLUDE` | `feat-review-flow` | 逗号分隔要跳过的 id；heavy 评审流（会推真实探针 change）默认跳过，改由**单独定时任务**执行（见 §5.1）；报告顶部注明"heavy 未纳入本轮" |
| `NEGATIVE` | false | 演示报告失败态：强制第一条判 FAIL（不改真实子 Job） |
| `TIMEOUT_MIN` | 20 | 总超时（分钟） |

构建完成后打开 `https://<PUBLIC_HOST>/reports/selfcheck/latest.html`（域名来自 `out/urls.env`）。首页固定卡「自检报告」与 `/status` 顶部也有直达链接。

## 3. 总判语义

| 总判 | 条件 |
|---|---|
| `PASS` | 所有选中项 SUCCESS |
| `PARTIAL` | 有 SKIPPED 但无 FAIL |
| `FAIL` | 任一 FAIL/UNKNOWN/ABORTED |

**SKIPPED 语义**：子 Job从未构建过（`build.number == 0` 或调用抛异常且无历史）记 SKIPPED，**不算 FAIL**，但计入报告顶部「未覆盖 N 项」警告。这样新增 Job 还没跑过时，不会让整个自检假红。要消除 SKIPPED，先手动跑一次该子 Job。

## 4. 怎么加检查项

1. 先建子 Job：在 `config/jenkins/jobs/` 加 `verify-<x>.groovy`（`pipelineJob('verify-<x>')`），Pipeline 放 `ci/jenkins/pipelines/verify-<x>.Jenkinsfile`。
2. 在 `ci/selfcheck/checks.tsv` 加一行：id 唯一、target = Job 名、`what` 写人话（报告里"这条测了什么"）、expect 目前只支持 `SUCCESS`、timeout 给秒数。
3. 在 `config/jenkins/jenkins.yaml` 的 `jobs:` 段加一行 `- file:`（容器内绝对路径）。
4. `make check` —— `check-selfcheck.sh` 会正向校验 target 存在、反向校验所有 `verify-*` Job 都在清单里；漏加任一项即红。
5. reload JCasC（`POST /configuration-as-code/reload`）让新 Job 生效，再跑一次 `selfcheck`。

> 反向门禁是防漂移关键：新增了 Job 却不加清单，`make check` 立即红；清单写了不存在的 target，同样红。

## 5. 报告保留与权限边界

- 保留：Jenkins Job `logRotator numToKeep=20`；报告每次写 `selfcheck-<build>.*`，`latest.*` 为最新指针。历史超过 20 次由人工/运维清理卷内旧文件（当前不做自动清理，避免误删）。
- 响应头：`Cache-Control: no-store`（`handle_path /reports/*` 块内），避免浏览器缓存旧报告。
- 权限：Jenkins 对卷 rw（写报告），Caddy 对同一卷 ro（只读发布）。**报告禁止含口令/私钥/内网 IP**：Pipeline 只写 id/title/what/result/duration/consoleUrl/证据，环境快照只记 commit/Jenkins 版本/镜像 tag 键名。验收用 `grep -i 'password\|PRIVATE' latest.html` 应为空。
- `verify-gerrit-review-flow` 是 heavy 项（建探针 change → 构建 → Verified +1 → abandon），默认可在 `EXCLUDE` 跳过；它自身无论成败都会 abandon 探针，保持 Gerrit open 列表干净。

### 5.1 heavy 评审流的调度（m2.5.5 加 cron → m3.0.3 T6 删除）

m2.5.5 曾给 `verify-gerrit-review-flow` 加 `cron('H 3 * * *')` 每天自动跑；**M3.0.3 T6 已删除该 cron**：服务随时可能被关停，夜间定时没有意义，还会留下"未观测"的记录。现由 selfcheck 显式调用或人工 `Build Now` 触发，不注册任何长定时。

- **结果在哪看**：Jenkins `job/verify-gerrit-review-flow/<build>/console`（"评审流闭环：change N Verified +1" + `abandon change N -> HTTP 200`）；Gerrit `gerrit query status:open` 应为 0。
- **日志保留**：该 Job 已配 `logRotator { daysToKeep(7); numToKeep(20) }`，探针 change 不会无限累积。

> **M3.0.4 T3 手动一键巡检 `make verify-all`**：`scripts/verify-all.sh` 按 `ci/selfcheck/checks.tsv` 顺序串行触发全部子 Job（默认排除 heavy `feat-review-flow`，共 21 项；`HEAVY=1` 连 heavy 一起跑共 22 项），逐项打印 SUCCESS/FAIL 并汇总 `TOTAL/PASS/FAIL/SKIP`。**只手动执行，不注册任何 cron/守护**——补的是 M3.0.3 移除长定时后"无人巡检"的缺口，而非恢复自动巡检（自动巡检属 M3.1 范围）。需要 `JENKINS_PASS` 认证：`JENKINS_PASS='...' make verify-all`。日常靠手动 `verify-all` + 封版检查表，不依赖"昨夜已跑过"。

### 5.2.1 备份可信自检（m3.0.1 T2）

备份纳入自检框架，坏了总报告必须红：

- **清单**：`ci/selfcheck/checks.tsv` 登记 `data-backup / job / verify-backup`（四列断言：latest≤26h + sha256sum -c + manifest 9卷/entries>0 + status.exit_code=0）。
- **Job**：`config/jenkins/jobs/verify-backup.groovy` + `ci/jenkins/pipelines/verify-backup.Jenkinsfile`（只读消费 `/data/backups`，挂到 agent `/opt/orgflow/backups:ro`，无 docker.sock、无 python3，用 jq+shell 校验）。任一项失败 `sh` 非零退出 → Jenkins `FAILURE` → selfcheck 该行 `FAIL` → 总判 `FAIL`（M2.5.5 教训：不写 description 冒充 PASS）。
- **挂载**：`services/jenkins-agent/compose.yml` 加 `/data/backups:/opt/orgflow/backups:ro`；latest 指针存宿主绝对路径，Job 内用 basename 映射到挂载点。
- **门禁**：`scripts/check-selfcheck.sh` 5f 校验四项断言关键字 + checks.tsv 的 data-backup 行。
- **反证**（2026-11-28 实测）：latest 指向 30h 前目录 → FAILURE(#5)；改坏一个 tar 字节 → sha256 FAILURE(#6)；status.exit_code=5 → FAILURE(#7)；恢复后 SUCCESS(#8)。

> 项数口径：文档原始提示词按 M2.4 的 20 项写"20→21"；M2.5.5 加 guard-quota-alive 到 21 项，M3.0.1 加 data-backup/data-drill 后为 23 项（报告默认排除 heavy 故 22 项）；**M3.0.3 T2 删除 data-drill 行后，checks.tsv 22 行、报告 21 项**。演练结果不再放进每次自检（否则"没演练就红、演练了也只绿一天"的假信号），改由封版检查表人工把关。

### 5.2.2 报告同源真校验（m3.0.2 T6）

M3.0.1 T4 的 `commit` 与 `deployedHead` 都取同一条 `git rev-parse HEAD`，旧 checkout 也恒 `consistent=YES`（同源自证缺陷，D6）。M3.0.2 改为**真校验**：

- **三字段**：`latest.json` 新增 `deployTag`（`git describe --tags --exact-match HEAD`，取不到写 `none`）与 `tagCommit`（该 tag 指向的 commit SHA，无 tag 则 `unknown`）；保留历史字段 `deployedHead`。
- **判据**：`consistent = commit == tagCommit && tagCommit != 'unknown'`；报告顶部显示 commit/tag/consistent 三行。只有 HEAD 正好在 tag 提交上（本轮 tag `m3.0.2-backup-truth`）才 `YES`；旧 checkout（无精确匹配 tag）→ `NO`。
- **Job 断言**：`verify-status-page` 读 `latest.json`，要求 commit/deployTag/tagCommit 三字段齐全、`deployTag != none`、`tagCommit != unknown`、`consistent=YES` 且 `commit==tagCommit`；反证旧 checkout 报告必 FAILURE。
- **门禁**：`check-selfcheck.sh` 5g 静态断言 `deployTag`/`tagCommit`/`describe --tags --exact-match HEAD`/`tagCommit != unknown` 齐全。
- **反证**：在没有打 tag 的旧 checkout（如 HEAD=`db5d78f`）跑 selfcheck → `deployTag=none`/`tagCommit=unknown`/`consistent=NO`；在 tag `m3.0.2-backup-truth` 对应提交上跑 → `consistent=YES`、`deployTag` 正确。

### 5.2.2a 报告时效规则（m3.0.5 T2 / D1）

旧报告页没有时间戳也没有过期提示，看起来像当前状态，实际可能是几小时前的旧口径（本次就是 22 项旧数据冒充当前）。M3.0.5 给报告加时效真源与前端过期标记：

- **JSON 字段**：`selfcheck.Jenkinsfile` 的 `latest.json` 新增 `generated_at`（UTC ISO8601，形如 `2026-11-29T03:29:15Z`，由 `date -u` 在发布阶段取）与 `generator`（`selfcheck#<build>`）。
- **HTML 时效块**：报告头部固定显示生成时间与"距现在 X 小时"。实现为自包含内联 JS（无外链，报告仍离线可读）：从时效块的 `data-generated-at` 取时间，按浏览器当前时间算 age。
  - `generated_at` 距今 **>24h**：整块标红（`.fresh.stale`）并写明"✗ 数据已过期，请重跑 selfcheck"。
  - 无 `generated_at`（旧版本报告）：显示"未知（旧版本报告）——无 generated_at，请重跑 selfcheck"并标红，不静默当新鲜。
  - 时间串不可解析：同样标红提示重跑。
  - 正常（≤24h）：显示"✓ 数据新鲜"。
- **Job 断言**：`verify-status-page` 新增 `report-freshness` stage——`latest.json` 必须有 `generated_at` 且可被 `datetime.fromisoformat` 解析、`generator` 非空，且 `latest.html` 必须内嵌同一时间串（前端据此算 age）。删字段 → FAILURE。
- **时序注意**：`feat-status` 行调 verify-status-page 时读的是**上一轮**报告，故切换报告口径后需连跑两次 selfcheck（第一次生成含新字段的报告 → 第二次 feat-status 读该报告转绿）。
- **门禁**：`check-selfcheck.sh` 静态断言 generated_at/generator/data-generated-at/"数据已过期"与 report-freshness 断言齐全。

### 5.2.3 演练结果可信（m3.0.2 T4/T5 → m3.0.3 T1/T2 改手动+字段化）

- **M3.0.3 T1**：演练改纯手动（`make drill` 前台跑 `drill-up.sh`），`verify-restore-drill` Job 删 cron、自检删 data-drill 默认项；演练结果由封版清单人工把关。
- **M3.0.3 T2 字段化断言**：`verify-restore-drill` 按 `drill.result` 字段断言（`result=PASS`/`healthy=3`/`repos=3`/`P_open=D_open`/`P_total=D_total`/`backup_sha256` 一致/`mode∈{quick,full}`），不再 grep 中文文案（E5）；**年龄 `age_h` 仅信息字段不判红**（反证：30 天前结果仍 SUCCESS 且 console 打印 age），但缺结果或 `result=FAIL` 仍 FAILURE（提示"请先 make drill"）。
- **M3.0.2 保留**：result.ts 与日志同源≤10min + JSON 可解析；changes 双指标 P_open/D_open、P_total/D_total（`--format=JSON` 三状态查询，私钥缺失直接 FAIL）；LDAP 口令 `docker exec -e` 注入无字面口令（E4）；`verify-backup` 断言 e（`status.verify.ok=true` 且 `failures` 为空）。

### 5.2 可信度修复（m2.5.5）

- **构建结果回写**（P0-2）：`selfcheck` 报告总判 `FAIL` 时同步设 `currentBuild.result=FAILURE`，`PASS/PARTIAL` 设 `SUCCESS`，与 description 的 `SELFCHECK <total> (FAIL=n ...)` 同口径。消除"报告红、构建绿"的假绿——通知/看板/API 现在能看出问题。反证：`NEGATIVE=true` 触发应 `Finished: FAILURE`，恢复后 `Finished: SUCCESS`。
- **mechanism 来源独立化**（P2-1）：报告 meta 的 `mechanism` 优先读 `/opt/orgflow/quota/mechanism.txt`，其次 `alive.json.mechanism`，都没有才 `unknown`；不再从 `guard-quota-alive` 行 description 提取，避免该行红了就把 mechanism 带崩成 unknown。
- **报告三字段一致**：`latest.json` 的 `overall`、`result` 同值，`mechanism` 独立来源；HTML meta 用 `overall` 口径。门禁 `check-selfcheck.sh` 静态断言字段齐全。

### Gerrit abandoned 探针保留策略（m2.5.3 P2-3）

`verify-gerrit-review-flow` 与端到端反证每轮都会留下 abandoned change（本轮定点时 `open=0 / abandoned=20`）。为留证据但避免无限累积，定策略：

- **保留最近 5 条** abandoned 探针样本，且这 5 条须**同时含成功样本与负例**（Verified +1 的 BUILD OK 与 BUILD BLOCKED 各至少 1 条）；其余按**季度清理**。
- 清理命令（列出但不必每轮执行；执行前先用 `gerrit query` 核对状态确为 ABANDONED）：
  ```bash
  # 查询 abandoned 探针（ci-bot + fixed known_hosts）
  ssh -i "$GERRIT_KEY" -p 29418 ci-bot@gerrit \
    "gerrit query --format=JSON status:ABANDONED owner:ci-bot" | jq -r .id
  # 保留最近 5 条，其余确认为探针后逐个清理（Gerrit 无内置批量删 abandoned，用 query + 人工核对）
  ```
- 历史证据链 change（如 #24/#25 这类被后续日志引用的锚点）不纳入季度清理，避免引用失效。

## 6. 刷新机制服务化与自启（m2.5.3 P0-1）

配额证据的自动刷新必须"扛过重启/长期运行"。按 **PID1** 选择机制，优先级从高到低：

| PID1 / 环境 | 机制 | 安装命令 | 拉起方式 |
|---|---|---|---|
| systemd | systemd timer（`OnBootSec=2min`/`OnUnitActiveSec=5min`/`Persistent=true`） | `make quota-install` | timer 周期触发，开机自启 |
| 有 crontab 命令 / cron.d | cron（用户 crontab 5 字段 或 `/etc/cron.d` 6 字段） | `make quota-cron-install` | cron daemon 周期触发 |
| supervisord | `[program:orgflow-quota]` + watchdog 兜底 | `make quota-supervisor-install` | supervisor autorestart + watchdog 10s 巡检 |
| runit | service run 脚本 | `make quota-runit-install` | `sv up` + runit supervise |
| 以上均无（最后兜底） | nohup 常驻循环 | `make quota-daemon-install` | 需在执行日志写明理由 |

- 三种管理器与 nohup 统一调用 `scripts/quota-guard-loop.sh`（每 300s 刷新 + 日志 >1MB 自轮转 + 写 `alive.json` 自证存活），刷新命令不再散落在 Makefile。
- **装服务前先 `make quota-cleanup-nohup`** 精确清理旧 nohup 进程（按 daemon.pid 且核对命令行含 `quota-guard-loop.sh`），绝不 `pkill -f quota-guard` 误杀手动调用；禁止两个刷新器并行写 `latest-of-builder.json`。
- `/etc/cron.d` 需 **6 字段**（第 6 字段为执行用户 root），用户 crontab 需 **5 字段**，两者不可混用；`quota-cron-install` 按分支选模板，安装后 `awk 'NF>=6 && $1!="#"'` 校验，不通过即退出。
- **验证自愈**：杀掉 loop 进程（`kill -9 $(cat artifacts/quota/daemon.pid)`）后 ≤60s 应拉起新 PID，`make quota-status` 的 `mechanism=` 与进程实际状态一致；`verify-quota-refresh` Job 校验「进程命令行匹配 + 日志新鲜≤8min + 证据 age≤10min」三项防假绿。详见[构建资源配额](构建资源配额.md)。

## 7. 故障排查

| 现象 | 处理 |
|---|---|
| `make check` 报 "Job 未登记" | 在 checks.tsv 补该 `verify-*` Job 一行 |
| 报告某行 SKIPPED | 先手动跑一次该子 Job，再跑 selfcheck |
| `guard-quota` 行红 / 报告 FAIL | 宿主未生成配额证据：先在宿主跑 `bash scripts/quota-guard.sh --container of-builder --out artifacts/quota`（或 `up.sh`，会在 builder/agent 启动后落证据）；确认 controller/agent 已挂 `/opt/orgflow/quota:ro`。证据 `verdict` 必须 PASS、`container=of-builder`、三项配额为 0。详见[构建资源配额](构建资源配额.md) |
| build-from-gerrit 卡在 `Quota gate` 报 `BUILD BLOCKED` | 证据过期（>10min）或非 PASS：在宿主重跑 `quota-guard.sh` 刷新 `latest.json`；refresh 后重新触发 change。agent 只读证据，不开 docker.sock |
| /reports/selfcheck/latest.html 404 | 确认共享卷挂载点为 `selfcheck-reports:/srv/reports/selfcheck:ro`（卷内文件在根，URL 经 `handle_path /reports/*` → `selfcheck/latest.html`）、Caddy `handle_path /reports/*` 生效、selfcheck 至少跑过一次；`curl -I` 应见 `Cache-Control: no-store` |
| selfcheck 卡在 "Waiting for next available executor on 'Jenkins'" | controller 需 1 个 executor 供 `node('built-in')` 读写清单/报告（`jenkins.yaml` 的 `numExecutors: 1`）；子 Job 仍在 orgflow-agent |
| 报告写文件抛 AccessDeniedException | 报告卷需属主 jenkins(uid1000)：`up.sh` 预建后以 root `chown 1000:1000`；手工修复见同脚本 |
| Pipeline 报 `Scripts not permitted: groovy.json...` | 沙箱未放行 groovy.json；本 Pipeline 用脚本级变量 + 字符串拼接，勿改回 JsonOutput/JsonSlurper |
| 报告页面含敏感字样 | 检查子 Job description 是否写了口令（evidence 取自 description），清理后重跑 |
| Gerrit 评审流探针 301/GnuTLS 失败 / commit email 无效 | 容器内经代理-http:8080 访问 Gerrit 必须注入 `Host: <canonicalWebUrl host>` + `X-Forwarded-Proto: https`（`git -c http.extraHeader` / `curl -H`），且 commit 用已注册邮箱（zeek.zhao@foxmail.com）；SSH 查询用 ci-bot + fixed known_hosts；探针 post.always abandon |
