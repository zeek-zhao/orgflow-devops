# 自检框架（M2.4 Phase3）

> 状态：适用 | 最后核对：2026-11-26 | 分支 `feat/m2-gerrit-cgit-harbor`
> 面向运维：如何跑自检、看报告、加检查项。面向写代码的人的手册见 [Gerrit 人工使用指南](../使用手册/Gerrit-人工使用指南.md)。

## 1. 它是什么

一条 Jenkins 编排 Job `selfcheck`（跑在 controller，`agent none`，只用 `build` 步骤调子 Job），按清单 `ci/selfcheck/checks.tsv` 逐条触发子 Job，汇总结果生成**自包含** HTML + JSON 报告，经共享卷由 Caddy 在公网发布到 `/reports/selfcheck/`。

- 清单真源：`ci/selfcheck/checks.tsv`（7 列：`id/kind/target/title/what/expect/timeout`）。
- 门禁：`scripts/check-selfcheck.sh`（接入 `make check`），保证清单与 Job 双向一致。
- 报告：`selfcheck-<build>.html/json` + `latest.html/json`，目录 `/reports/selfcheck`（Jenkins rw）/ `/srv/reports`（Caddy ro）。

## 2. 跑自检

Jenkins → `selfcheck` → `Build with Parameters`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `INCLUDE` | 空 | 逗号分隔 id；留空 = 全部 |
| `EXCLUDE` | `feat-review-flow` | 逗号分隔要跳过的 id；M2.5 P2-2 起重项默认跳过（会推真实探针 change），改由单独定时执行；报告顶部注明"heavy 未纳入本轮" |
| `NEGATIVE` | false | 演示报告失败态：强制第一条判 FAIL（不改真实子 Job） |
| `TIMEOUT_MIN` | 20 | 总超时（分钟） |

构建完成后打开 `https://<PUBLIC_HOST>/reports/selfcheck/latest.html`（域名来自 `out/urls.env`）。首页固定卡「自检报告」与 `/status` 顶部也有直达链接。

## 3. 总判语义

| 总判 | 条件 |
|---|---|
| `PASS` | 所有选中项 SUCCESS |
| `PARTIAL` | 有 SKIPPED 但无 FAIL |
| `FAIL` | 任一 FAIL/UNKNOWN/ABORTED |

**SKIPPED 语义**：子 Job从未构建过（`build.number == 0` 或调用抛异常且无历史）记 SKIPPED，**不算 FAIL**，但计入报告顶部「未覆盖 N 项」警告。这样新增 Job 还没跑过时，不会让整个自检假红。要消除 SKIPPED，先手动跑一次该子 Job。

## 4. 怎么加检查项

1. 先建子 Job：在 `config/jenkins/jobs/` 加 `verify-<x>.groovy`（`pipelineJob('verify-<x>')`），Pipeline 放 `ci/jenkins/pipelines/verify-<x>.Jenkinsfile`。
2. 在 `ci/selfcheck/checks.tsv` 加一行：id 唯一、target = Job 名、`what` 写人话（报告里"这条测了什么"）、expect 目前只支持 `SUCCESS`、timeout 给秒数。
3. 在 `config/jenkins/jenkins.yaml` 的 `jobs:` 段加一行 `- file:`（容器内绝对路径）。
4. `make check` —— `check-selfcheck.sh` 会正向校验 target 存在、反向校验所有 `verify-*` Job 都在清单里；漏加任一项即红。
5. reload JCasC（`POST /configuration-as-code/reload`）让新 Job 生效，再跑一次 `selfcheck`。

> 反向门禁是防漂移关键：新增了 Job 却不加清单，`make check` 立即红；清单写了不存在的 target，同样红。

## 5. 报告保留与权限边界

- 保留：Jenkins Job `logRotator numToKeep=20`；报告每次写 `selfcheck-<build>.*`，`latest.*` 为最新指针。历史超过 20 次由人工/运维清理卷内旧文件（当前不做自动清理，避免误删）。
- 响应头：`Cache-Control: no-store`（`handle_path /reports/*` 块内），避免浏览器缓存旧报告。
- 权限：Jenkins 对卷 rw（写报告），Caddy 对同一卷 ro（只读发布）。**报告禁止含口令/私钥/内网 IP**：Pipeline 只写 id/title/what/result/duration/consoleUrl/证据，环境快照只记 commit/Jenkins 版本/镜像 tag 键名。验收用 `grep -i 'password\|PRIVATE' latest.html` 应为空。
- `verify-gerrit-review-flow` 是 heavy 项（建探针 change → 构建 → Verified +1 → abandon），默认可在 `EXCLUDE` 跳过；它自身无论成败都会 abandon 探针，保持 Gerrit open 列表干净。

## 6. 故障排查

| 现象 | 处理 |
|---|---|
| `make check` 报 "Job 未登记" | 在 checks.tsv 补该 `verify-*` Job 一行 |
| 报告某行 SKIPPED | 先手动跑一次该子 Job，再跑 selfcheck |
| `guard-quota` 行红 / 报告 FAIL | 宿主未生成配额证据：先在宿主跑 `bash scripts/quota-guard.sh --container of-builder --out artifacts/quota`（或 `up.sh`，会在 builder/agent 启动后落证据）；确认 controller/agent 已挂 `/opt/orgflow/quota:ro`。证据 `verdict` 必须 PASS、`container=of-builder`、三项配额为 0。详见[构建资源配额](构建资源配额.md) |
| build-from-gerrit 卡在 `Quota gate` 报 `BUILD BLOCKED` | 证据过期（>10min）或非 PASS：在宿主重跑 `quota-guard.sh` 刷新 `latest.json`；refresh 后重新触发 change。agent 只读证据，不开 docker.sock |
| /reports/selfcheck/latest.html 404 | 确认共享卷挂载点为 `selfcheck-reports:/srv/reports/selfcheck:ro`（卷内文件在根，URL 经 `handle_path /reports/*` → `selfcheck/latest.html`）、Caddy `handle_path /reports/*` 生效、selfcheck 至少跑过一次；`curl -I` 应见 `Cache-Control: no-store` |
| selfcheck 卡在 "Waiting for next available executor on 'Jenkins'" | controller 需 1 个 executor 供 `node('built-in')` 读写清单/报告（`jenkins.yaml` 的 `numExecutors: 1`）；子 Job 仍在 orgflow-agent |
| 报告写文件抛 AccessDeniedException | 报告卷需属主 jenkins(uid1000)：`up.sh` 预建后以 root `chown 1000:1000`；手工修复见同脚本 |
| Pipeline 报 `Scripts not permitted: groovy.json...` | 沙箱未放行 groovy.json；本 Pipeline 用脚本级变量 + 字符串拼接，勿改回 JsonOutput/JsonSlurper |
| 报告页面含敏感字样 | 检查子 Job description 是否写了口令（evidence 取自 description），清理后重跑 |
| Gerrit 评审流探针 301/GnuTLS 失败 / commit email 无效 | 容器内经代理-http:8080 访问 Gerrit 必须注入 `Host: <canonicalWebUrl host>` + `X-Forwarded-Proto: https`（`git -c http.extraHeader` / `curl -H`），且 commit 用已注册邮箱（zeek.zhao@foxmail.com）；SSH 查询用 ci-bot + fixed known_hosts；探针 post.always abandon |
