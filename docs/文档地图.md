# 文档地图

> 这是 docs/ 的唯一根索引。每个子目录有自己的 README 索引（见下表）。
> 每篇文档的 DOC-ID、状态、负责人、复审节奏在 [文档登记册](文档登记册.md)。

## 目录结构

| 目录 | 装什么 | 索引 |
|---|---|---|
| `project/` | 项目治理：章程、项目管理、风险、质量、验收、问题索引 | [project/README](project/README.md) |
| `engineering/` | 工程规程：使用说明、生命周期、门禁、配置、发布、测试体系 | [engineering/README](engineering/README.md) |
| `services/` | 服务手册：每个服务一册 | [services/README](services/README.md) |
| `records/` | 决策与归档：开源合规、ADR、历史设计 | [records/README](records/README.md) |
| `network/` | 网络架构 | [network/README](network/README.md) |
| `requirements/` | 需求基线（REQ-M0-xx） | [requirements/README](requirements/README.md) |
| `_templates/` | 文档模板（不登记） | - |

## 三个常见误区

1. **想找「这个服务怎么配」** → 先去 [services/](services/README.md)，别翻根目录；
2. **以为 docs/ 根目录应该有正文** → 根目录只放索引（本文件 + 登记册），正文都在子目录；
3. **新增文档忘了登记** → `make docs-check` 会红，登记要求见 [文档规范](engineering/文档规范.md)。
