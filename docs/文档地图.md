# 文档地图

> 这是 docs/ 的唯一根索引。每个子目录有自己的 README 索引（见下表）。
> 每篇文档的 DOC-ID、状态、负责人、复审节奏在 [文档登记册](文档登记册.md)。

## 目录结构

| 目录 | 装什么 | 索引 |
|---|---|---|
| `project/` | 项目治理：章程、项目管理、风险、质量、验收、问题索引 | [project/README](project/README.md) |
| `engineering/` | 工程规程：使用说明、生命周期、门禁、配置、发布、测试体系、经验教训、服务×需求×测试矩阵 | [engineering/README](engineering/README.md) |

| `network/` | 网络架构：图版（架构图）与 IP/端口拓扑（arch.md） | [network/README](network/README.md) |
| `requirements/` | 需求基线（REQ-M0-xx） | [requirements/README](requirements/README.md) |
| `_templates/` | 文档模板：ADR、服务手册（不登记） | - |

## 按问题找文档

| 你想… | 去哪 |
|---|---|
| 从零部署一次 | [使用说明](engineering/使用说明.md) §0（踩坑记录在 [经验教训](engineering/经验教训.md)） |
| 看整体长什么样、账号口令在哪登 | [架构图](network/架构图.md)（图 + 账号口令总表），IP/端口在 [arch.md](network/arch.md) |

| 知道某需求谁实现、哪个用例守着 | [服务×需求×测试矩阵](engineering/服务×需求×测试矩阵.md) |
| 看要求什么、怎么算做到 | [requirements/](requirements/README.md)（REQ-M0-xx） |
| 查历史坑 | [经验教训](engineering/经验教训.md)（唯一真源，别处只放链接） |

## 三个常见误区

1. **以为 docs/ 根目录应该有正文** → 根目录只放索引（本文件 + 登记册），正文都在子目录；
2. **新增文档忘了登记** → `make docs-check` 会红，登记要求见 [文档规范](engineering/文档规范.md)；
3. **在经验教训.md 之外又写了一份踩坑清单** → 教训只收在经验教训.md，其它文档放链接，否则两份清单必有一份过时。
