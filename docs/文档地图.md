## 三个常见误区

1. **拿「验收记录」当设计文档**：它记的是「那天验过什么」，不是「系统应该怎么设计」。
   设计意图在 [M0-最小核心](M0-最小核心.md) 与 [ADR-13](ADR-13-域名路由.md)。
2. **拿「会话交接」当权威**：它是快照。冲突时以代码、`config/`、`docker-compose.yml` 为准。
3. **改了架构只改手册**：顺序必须是 ADR → 服务手册 → 入口索引。反过来就会出现
   「手册比 ADR 新」的矛盾态，下一个接手人只能猜哪个对。
