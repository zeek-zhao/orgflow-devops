# 分支与合并策略

> 状态：适用 | 最后核对：2026-11-24 | 交付主线：`feat/m0-release`（main 不参与，保持 9db08e3）

## 合并方向（M0 收口口径，2026-11-24 起）

```
feat/m0-v2 (aa81fa5)  ──拉出──▶  feat/m0-release（M0 总分支 / 长期交付主线）
                                        │
                                        ├──拉出──▶ feat/m0-release-rc（整理分支）
                                        │                │
                                        │          功能分支 fix/m0-r<N>-<slug>
                                        │                │ PR（禁止直推）
                                        │                ▼
                                        └──merge── feat/m0-release-rc ──merge──▶ feat/m0-release
                                                                                    │ tag m0-v1.0（封版）
main（9db08e3，只读历史参考，不合并 / 不打 tag / 不改写）
```

- **功能分支 → feat/m0-release-rc**：每个收口任务（R1/R2/R3…）从 rc 起独立分支
  `fix/m0-r<N>-<slug>`，一个 Issue + 一个 PR，PR 正文首行 `Closes #<issue>`。
- **feat/m0-release-rc → feat/m0-release**：整理分支验证后合入交付主线，**禁止功能分支直推 release**。
- **M0 封版**：在 `feat/m0-release` 打轻量 tag `m0-v1.0`，**不要求 main 同步、不合并 main**。
- 合并方式：**merge commit**（保留分支拓扑，每次合入 release 可见 merge 提交）；禁止 Squash / rebase 改写已推送历史。

## 硬规则

1. **动平台 / 镜像 / 网络的功能分支，一律不得直接 push 到 release / rc**——必须走 PR。
2. 顶层不得出现 `docker-compose.yml`；启停一律 `./up.sh`，单服务 `--only` / `--recreate`，禁止全量 `down`。
3. 不重启整机、不重建 docker 网络、不重建数据卷；线上是长期在线 sandbox。
4. 域名走 `DOMAIN` / `PUBLIC_HOST` 配置 + Caddy `{$DOMAIN}` 占位符，不写死；镜像引用必须 `@sha256` 或 lock 校验通过的 `orgflow/m0-*`（仅 `USE_LOCAL_IMAGES=1` 启用）。
5. 每次操作写入 `docs/records/执行日志/<日期>.md`：命令 + 退出码 + 关键输出 + 结论。
6. `main` 不参与本轮任何操作；不 force push；不删既有文档（过时标「已废弃」）。
