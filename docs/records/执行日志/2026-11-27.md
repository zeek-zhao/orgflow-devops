### m2.5.5 自检可信度修复与 M2 封版收口（基线 2b841ae / tag m2.5.4-quota-single-instance）

依据《OrgFlow M2.5.5 自检可信度与 M2 封版 · AI 提示词》。现场事实：自检 #17 报告 `overall=FAIL result=FAIL fail=1 mechanism=unknown`，20 行中 `guard-quota-alive` 红——`instances=1 pidfile_pid=0 pid=9778`，但 Jenkins 构建仍是绿的（"假绿"）。根因：loop 只在启动时写一次 `daemon.pid`，沙箱重启/cleanup 删除后永不重建。本轮修三处自检可信度问题 + 补一个"说了没做"的定时任务，然后做 M2 封版终验。不放宽任何阈值、不把 FAIL 写成 PASS。

#### P0-1 pidfile 心跳续约 + cleanup 守卫 + 双启动拒绝
- `scripts/quota-guard-loop.sh`：`refresh_loop()` 每轮开头 `echo "$$" > "$OUT/daemon.pid"`（"心跳即续约"，删后 ≤INTERVAL 默认 5min 自愈）；启动守卫——若 pidfile 指向另一个存活且 cmdline 确为 loop 的进程，`exit 4` 拒绝启动（防 supervisor 与 watchdog 同时拉起双实例）。新增 `--count-instances` 参数供守卫复用同一套 `/proc` 精确 argv 计数。
- `Makefile quota-cleanup-nohup`：先按 pidfile 精确 kill 旧 loop，再用 `--count-instances` 复核全场；仅 `instances==0` 才 `rm -f pidfile`，有存活 loop 则保留并打印"⚠ 仍有 N 个存活 loop，保留 pidfile 不删"。
- **实测**：`kill -9 9778`（旧 loop）→ watchdog 用新脚本拉起新 PID **29224**；pidfile=29224、alive `pidfile_pid=29224==pid`、instances=1。再起第二个 loop（`bash scripts/quota-guard-loop.sh`）→ console `✗ pidfile 指向存活 loop PID=19199（≠自身），拒绝启动避免双实例（exit 4）`，实例数仍 1。删 pidfile 后下一轮心跳/重启即刻重建（见反证②）。
