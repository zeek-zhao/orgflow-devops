- **背景**：M1 镜像拉取曾因 `/var/lib/docker`（vfs 驱动）所在 overlay2 沙箱层仅 9.8G、已用 97%（剩 334M）导致写层失败。本次先按「不使用沙箱」要求复查环境，再迁移主实例 data-root 到 `/dev/vdd`（125G ext4，可用 ~118G，挂载 `/ags/workbuddy-data`）。
- **根因**：`/etc/docker/daemon.json` 为 `{"storage-driver":"vfs"}`，vfs 不共享层、逐层完整复制，`/var/lib/docker/vfs/dir` 膨胀到 8.9G；data-root 绑死在满的沙箱 overlay。单纯跳出沙箱执行命令不会改变 daemon 已绑定的 data-root。
- **架构探查**：主 dockerd 由 supervisord `[program:docker]`（`/usr/local/bin/dockerd-entrypoint.sh`，autorestart=true）托管；另有哨兵进程监控 `/var/run/cloudstudio/dockerd/.dockerd`，删除该文件会 `pkill -2 dockerd`。启动脚本未显式指定 `--data-root`，故 data-root 完全由 daemon.json 控制 → 改配置即可。
- **迁移步骤（保留原数据作回滚底牌，copy 而非 move）**：
  1. 导出容器/卷/网络清单到 `/ags/workbuddy-data/container-inventory-before.tsv`。
  2. 优雅停 6 容器 → supervisor RPC `stopProcess('docker')` 停 dockerd。
  3. `cp -a /var/lib/docker/. /ags/workbuddy-data/docker-main/`（21m43s；8.9G，文件数 src=246613 = dst=246613 校验一致）。
  4. `daemon.json` 改为 `{"storage-driver": "vfs", "data-root": "/ags/workbuddy-data/docker-main"}`（原文件备份 `/ags/workbuddy-data/daemon.json.bak`）。
  5. 重启 dockerd：supervisor 状态机多次卡在陈旧 Running（stop/start 返回 True 但状态不刷新），最终以 `dockerd-entrypoint.sh` 后台启动并稳定运行；清理重复实例后只保留一个 dockerd。
  6. of-caddy 因陈旧端口绑定 `443:443` 与 Tailscale Funnel（tailscaled 监听 443）冲突启动失败 → 打本地镜像标签 `orgflow/m0-caddy:v2`（源 3067cc4e02c0，`pull_policy: never` 避免国内代理 403），用正确 project 强制重建：`COMPOSE_PROJECT=orgflow-minimal docker compose --env-file config/defaults.env --env-file config/images.env -p orgflow-minimal -f services/caddy/compose.yml up -d --no-deps --force-recreate caddy`，容器恢复 `8080:80 / 8443:443 / 18081` 绑定。
- **验收（真实输出）**：`docker info` → Docker Root Dir `/ags/workbuddy-data/docker-main`、Storage Driver vfs、Containers 6 / Images 6；6 容器全部 healthy；`df -h /ags/workbuddy-data` → 125G 用 9.7G/剩 109G；Caddy 18081（Host 头）→ HTTP 200；Tailscale Funnel 公网域名 → HTTP 200。
- **遗留/注意**：
  - supervisor 的 docker program 状态机在反复 stop/start 后失同步，当前 dockerd 由手工后台进程持有而非 supervisor 托管；沙箱若重启需核对 `daemon.json` 的 data-root 已生效并确认 dockerd 正常拉起（必要时手动 `bash /usr/local/bin/dockerd-entrypoint.sh`）。
  - 国内代理拉镜像仍 403（docker.nju.edu.cn 拒绝），属网络问题非空间问题；空间已充足，后续拉 M1 镜像仍需换可用 GHCR 代理源。
  - 旧 `/var/lib/docker`（8.9G）保留未删，作回滚底牌；确认稳定后可清理回收沙箱层空间。
