## 2. 拆除与重建过程

1. **拆除**：`down.sh` 静默失败——容器实际 project 为 `orgflow-minimal`/`jenkins` 混杂，脚本用 `-p orgflow-<svc>` 找不到容器。改用 `docker rm -f $(docker ps -aq --filter name=^of-)` 强制删除全部 9 个容器（含孤儿 `of-j-debug5`），**保留 4 个数据卷 + 1 个网络**，CA 哈希复核未变。
2. **重建**：`up.sh` 逐服务起在前两个服务（dnsmasq、certs-init）因 compose pull/create 竞态报 UNHEALTHY（错误被 `>/dev/null` 吞、cid 未及时出现）。改为按 manifest 顺序手动 `docker compose up -d --no-deps` 逐服务起。
3. **jenkins/agent**：compose 默认镜像 `ghcr.io/...:ctx-*` 走直连 TLS 超时；本地已有同内容代理镜像（`ghcr.nju.edu.cn/.../m1-jenkins:<none>`），用镜像 ID 打上 compose 期望的 `ctx-*` tag，再以 `--pull never` + 从 `secrets/` 注入 SSH/host key 启动。
4. **幂等确认**：重建完成后 `up.sh --no-pull` 再跑一次，9 步全部 `skip (already healthy)`，无 recreate、无拉取。

## 3. 判据 7/8 修复（本次终验发现的历史假绿）

文档 A 部分声称「状态页已切到 router」通过，但实测 `/status` 返回 **HTTP 501**（HEAD 未实现），正文为静态 HTML——无 `status-source` 头、无 `of-` 容器名、router 日志被 `log_message` 静默。根因是 `services/router/server.py` 从未实现终验判据要求的三点（仓库历史无 `status-source` 踪迹），r5 状态页去重只做了反代、未补齐验收面。

修复（最小改动，不动路由真源逻辑）：
- `_send` 增加 `extra_headers` 参数；`do_GET /status` 返回 `Status-Source: router` 头并打印访问日志。
- 新增 `do_HEAD`，`curl -sI` 返回 200 + 同头、无 body。
- 状态页表格增加「容器」列，列全 9 个 `of-*`（含 `of-jenkins`、`of-jenkins-agent`），每行一个 `of-`，`grep -c 'of-'` = 9。
- `server.py` 为 bind mount，重建 router 容器（`--force-recreate --pull never`）即生效，无需重建镜像。
