# M0 治理约定

> 本分支从零实现，`main` 为只读历史参考分支，**不参与 M0 任何操作**（不合并 / 不打 tag / 不推送 / 不改写，保持 `9db08e3`）。M0 交付主线是 `feat/m0-release`。规则来自方案书 v0.2 §4 / §6 / §5，分支口径以 2026-11-24《M0 收口提示词》为准。

## 分支模型（M0 收口口径，2026-11-24 起生效）

```
feat/m0-v2 (aa81fa5)
      │
      └── feat/m0-release        ← M0 总分支（长期存在，交付主线，所有修复汇此）
              │
              └── feat/m0-release-rc  ← 整理分支（一个 PR 一个问题，修完合回 release）
```

| 项 | 规则 |
|---|---|
| 交付主线 | `feat/m0-release`，长期分支，M0 封版在此打 tag `m0-v1.0`（不要求 main 同步） |
| 整理分支 | `feat/m0-release-rc`，从 release 拉出；R1/R2/R3 等修复 PR 以此为目标 |
| 功能分支 | 从 rc 切出：`fix/m0-r<N>-<slug>` / `feat/m0-r<N>-<slug>` |
| 合并方向 | 功能分支 → `feat/m0-release-rc`（PR，merge commit）→ 合入 `feat/m0-release`；禁止直推 |
| main | 只读历史参考，保持 `9db08e3`，不合并、不打 tag、不改写 |
| 禁止 | 直推 release/rc；force push；删既有文档（过时标「已废弃」）；手工关 Issue（PR 正文首行 `Closes #N`） |

### 废弃分支（标注不删除）

`feat/m0-minimal`、`feat/m0-final-pr`、`feat/m0-adopt-main-images`、`feat/m0-t2-images`、`feat/ghcr-ci-images` 均已废弃，作为历史档案保留，不再合入、不再推送。旧口径「`feat/m0-minimal` → `main` 一条总 PR」已作废。

## PR 约定

- 标题：`feat(<area>): T<N> <一句话>`，area ∈ {dns,cert,proxy,ldap,panel,router,ci,ops,docs}
- 描述首行 `Closes #<issue>`，合并即自动关单
- 单一功能，≤15 文件；三条必需检查（Compliance / Test / Identity）全绿
- `make record` 的本条记录先提交进分支

## 记录留存

- `docs/records/执行日志/<YYYY-MM-DD>.md`：时间 / 执行者 / Issue / 命令 / 输出摘要 / 结论
- `docs/records/执行日志/artifacts/`：命令原文原样落盘，不截断
- `docs/records/M0-变更台账.md`：一 PR 一行，脚本维护，按 issue 去重
- 执行日志是运行产物，不进文档登记册
