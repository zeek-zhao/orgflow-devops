# 风险与应对

> 规程性质：已知风险的应对**机制**，不是状态台账——风险状态写在对应 Issue 里，
> 本文只保留「怎么发现、怎么防、真发生了怎么办」。

## 1. 风险清单与应对

| 风险 | 发现手段 | 应对 |
|---|---|---|
| 镜像落后于源码（拉取成功但跑旧代码） | `make images-guard` 在 deploy 前拦截 | 走 [版本与发布](../engineering/版本与发布.md) §发布准入三步 |
| 示例口令/弱口令上生产 | `make redaction` + deploy 口令体检（占位值自动随机化） | 真值只在部署机 `.env`；文档只留占位符 |
| 公开面泄漏内网信息/凭据 | `make redaction`（PUBLIC 面扫描） | 见 [开源合规 §维护](../records/开源合规.md) |
| 提交身份漂移（AI/CI 代提交） | `Identity` 工作流 + 钩子 | 见 [AI-协作开发](../engineering/AI-协作开发.md) |
| 备份损坏/恢复失败 | `--verify` + restore guards + 演练 | [备份与恢复](../engineering/备份与恢复.md) |
| 文档与实现漂移（文档烂没人知） | `docs-check`/`links`/服务手册四段门禁/矩阵登记 | [文档规范](../engineering/文档规范.md) + [矩阵](../engineering/服务×需求×测试矩阵.md) |
| 测试环境跨轮污染（DinD 卷残留） | entrypoint teardown 清卷 | 见 [经验教训](../engineering/经验教训.md)§测试与环境 |
| 凭据长期不轮换 | 部署时随机生成（deploy 口令体检） | 轮换走 `make ldap-apply` + nexus 改密，见使用说明 §5 |

## 2. 新风险的入口

发现新风险 → 建 Issue（`type/ops` 或 `type/compliance`，里程碑归 M0/M1）→
若需要**机制级**应对，改本文表格；一次性处置留在 Issue 里不进本文。
