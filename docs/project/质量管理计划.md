# 质量管理计划

> 状态：review ｜ 负责人：zeek.zhao ｜ 层级：规程（DOC-P-013）
> 三层验证的能力边界见 [M0 测试体系](../engineering/M0-测试体系.md)，门禁分层见 [CI 门禁分层](../engineering/CI门禁分层.md)。
>
> 本文把散落在 AGENTS.md、文档规范、测试体系里的质量口径收成一份：
> **质量目标 → 验证手段 → 门禁反证 → 度量命令 → 评审与审计**。

## 1. 质量目标

| 目标 | 可度量的判据 | 谁查 |
|---|---|---|
| 可复现 | 每个结论都能写成一条可照抄的命令与期望输出 | 评审者 / [AI 协作开发](../engineering/AI-协作开发.md) 三件套 |
| 公开面干净 | 内网标识、凭据形态、内部流程文档 0 命中 | `make redaction` |
| 引用自洽 | 仓内 0 死链、文档登记册双向一致 | `make links`、`make docs-check` |
| 身份唯一 | author 与 committer 唯一、无 AI 署名尾注 | `make identity-check` |
| 门禁能反证 | 改坏一处必红、恢复必绿 | 每次改门禁时贴反证 |
| 镜像与源码一致 | digest 锁定且未落后于源码 | `make images-guard` |

## 2. 验证手段与能力边界

| 层 | 手段 | 能证明 | 证明不了 |
|---|---|---|---|
| 静态 | `make test`、`make check` | 配置结构、脚本逻辑、文档与 compose 一致 | 任何运行时行为 |
| 集成 | `make test-bats` | 栈能起、路由能通、TLS 链对 | Jenkins job 能不能跑 |
| 人工三段 | [M0 测试体系](../engineering/M0-测试体系.md) | 全链路真能用 | 没手动走过的那条路 |

**三层不能互相替代**。M0 关闭时暴露的三个真机缺陷，全是「上层绿了但下层没验」。
因此准出判据必须三层分别列，不能只写「CI 绿」。

## 3. 门禁反证（硬要求）

改任何断言、判据、门禁脚本，PR 里必须同时贴两半：

1. **改坏一处 → 门禁必须红**（给出命令与红的输出行）
2. **恢复 → 绿**

只贴绿的那半不算验证。历史代价写在 [AGENTS.md](../../AGENTS.md)「遇到红怎么办」
与 [问题索引](问题索引.md) §6：#57 的登录页 200 被当成「已放行」，是判据本身写错；
#132 的三红里有一条是 force-push 后 `before` 不可达，不是间歇故障。

禁止的做法（写下来是因为出现过）：

- 不写 `|| true`、不 `SKIP_BATS=1` 静默跳过（跳过必须打印「CI 会跑」）
- 不为让检查变绿放宽断言或删用例
- 不改 `tests/images.lock` 里的 digest 来「修红」
- 不把 WARN 当绿，也不为消 WARN 放宽判据

## 4. 度量命令

```bash
make check
make check-all
make docs-check
make links
make redaction
make test
make test-bats
make identity-check
make images-guard
make sbom
make cve
```

`make cve` 未装 trivy 时明确失败退出（不让「没扫」被当成「扫过且干净」），
当前策略是**先出账不阻断**，阈值待基线建立后再定，见 [开源合规](../records/开源合规.md) §4。

## 5. 评审与审计节奏

| 频率 | 动作 | 产出 |
|---|---|---|
| 每次 PR | `make check` 打底，改文档另跑 `make docs-check` | CI 红灯即阻断 |
| 每次推送 | `make check-all`（或直接让 pre-push 钩子跑） | 全栈行为断言 |
| 每次发版 | §4 全部命令 + [验收与交付准则](验收与交付准则.md) 准出清单 | 发布记录 |
| 每月 | 看 `make docs-check` 的 WARN 决定续期/退役 | 登记册更新 |
| 每季度 | 复核本文 §1 目标是否仍成立 | 本文或 [文档规范](../engineering/文档规范.md) 更新 |

## 6. 缺陷与不合格处置

红项先按三类归因再动手（[AGENTS.md](../../AGENTS.md)、[问题索引](问题索引.md) §6）：

| 类别 | 改法 |
|---|---|
| 真缺陷 | 改实现，开 BUG-<Issue号> |
| 判据没跟上变化（假红） | 修门禁，并贴「改坏→红、恢复→绿」反证 |
| 环境差异 | 写清环境边界，不改断言 |

三条以上同源失败先停下来写根因，不要逐个打补丁。
