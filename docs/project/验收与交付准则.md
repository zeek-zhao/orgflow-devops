## 1. 两个容易混的「双」，先定义

| 术语 | 指什么 | 真本在哪 |
|---|---|---|
| 双操作入口 | Jenkins 参数化 Job 与命令行 `make` 两套操作方式 | [使用说明](../engineering/使用说明.md) §6、[M0 最小核心](../records/M0-最小核心.md) Job 表 |
| 双验收入口 | Linux 侧 `scripts/deploy.sh` 的期望值，与 Windows 侧 `tools/win-acceptance/Test-OrgflowAcceptance.ps1` 的期望值 | [文档规范](../engineering/文档规范.md) §7.1（#134 要求两处期望值都带出处） |
| 三段验收 | compose / job / Windows 三段人工验收 | [M0 最小核心](../records/M0-最小核心.md)、[M0 测试体系](../engineering/M0-测试体系.md) |

「双入口」不是仓库原有术语，引用前先按上表定位，别造空概念。

## 2. 准入

| 条件 | 复现命令 |
|---|---|
| 需求条目有冻结的要求与判据 | 查 [需求基线](../requirements/README.md) 四列语义 |
| 改动有对应 Issue 与 PR | `gh issue view <号>` |
| 提交身份合规 | `make identity-check` |
| 文档与登记册一致 | `make docs-check` |
| 无死链、无敏感串 | `make links`、`make redaction` |

## 3. 准出

| 段 | 判据 | 不复现就不算过 |
|---|---|---|
| 静态 | `make check` 七项 + `make test` 全绿 | 贴命令输出 |
| 集成 | `make test-bats` 全绿 | 贴用例通过数；有红按 [问题索引](问题索引.md) §6 归因 |
| compose | 容器 healthy、固定 IP 表一致、站点状态码、Jenkins 鉴权、节点在线 | 见 [M0 测试体系](../engineering/M0-测试体系.md) |
| job | 跑一次部署类 Job，站点从不可用变可用，重跑幂等 | 同上 |
| Windows | 验收脚本 EXITCODE=0；hosts 条目数、根证书、`--noproxy` 三项都核 | 同上 |
| 公开面 | 脱敏 / 死链 / SBOM / CVE 四项 | [开源合规](../records/开源合规.md) §4 |

**判据不能全写 200**：未登录时 Jenkins、ldapadmin、auth 的期望值本就不是 200，
Dex 根路径是 404 要打健康端点。写成一律 200 会得到 #57 那种假绿。

## 4. 交付物清单

| 类别 | 交付物 |
|---|---|
| 代码与配置 | PR diff、`config/` 变更、`docker-compose*.yml` 变更 |
| 镜像 | GHCR 包与 `@sha256:` 锁定，见 [版本与发布](../engineering/版本与发布.md) |
| 文档 | 设计/服务手册/登记册/地图同步，见 [文档规范](../engineering/文档规范.md) §6 |
| 测试 | 新增或更新的断言 + 反证，见 [质量管理计划](质量管理计划.md) §3 |
| 合规 | `THIRD_PARTY_NOTICES.md`、`licenses/`、`out/sbom.spdx.json`、`out/cve/` |
| 运维 | 备份包与恢复演练结论，见 [备份与恢复](../engineering/备份与恢复.md) |

## 5. 关单取证格式

Issue 关闭时贴**命令与实测输出**，不写「已验证」三个字（[文档规范](../engineering/文档规范.md) §7）：

```
命令：<可照抄的一行>
期望：<状态码 / 断言 / digest>
实测：<输出行>
反证：<改坏一处后门禁红的输出行>
结论：回填需求基线「现状」列
```

结论回填 [需求基线](../requirements/README.md) 的「现状」列；
预期与实测不一致时按 [问题索引](问题索引.md) §6 分成「判据错」还是「实现错」，
判不出来就停下来写成 issue，别猜。
