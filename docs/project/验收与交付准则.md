# 验收与交付准则

> 规程性质：什么算「交付完成」。每条需求的验收判据正文在
> [requirements/](../requirements/README.md)；本文定义验收的组织方式与判据纪律。

## 1. 术语（本仓库约定）

- **双操作入口**：每个关键操作都有一条「文档化命令路径」与一条「Jenkins Job 路径」
  （例：Nexus 部署 = `bash scripts/nexus-deploy.sh` 或 nexus-deploy Job），两者幂等且一致；
- **双验收入口**：CI DinD 全栈用例（全新环境）+ 真机人工三段验收（真实部署环境）；
- **三段验收**：①栈健康（容器 healthy + 入口清单）→ ②行为抽检（登录/推拉/构建）→
  ③数据留存（备份恢复 round-trip）。

## 2. 判据纪律

- **判据不能全写 200**：入口返回 200 只证明网关通；行为抽检（写路径、错凭据拒绝、
  反证）必须做。`200 ≠ 能用`。
- 每条 REQ 的判据包含反证（改坏必须红）；验收时同样要留反证证据。
- 「跳过」字样的日志当红看：改密跳过、重建跳过都可能是配置没到（见
  [经验教训](../engineering/经验教训.md)§部署与脚本）。

## 3. 验收流程

1. CI 必需检查全绿（Test / Compliance / Identity）；
2. 真机三段验收按 [使用说明 §0](../engineering/使用说明.md) 的步骤走完，
   入口清单与端点自检输出留档；
3. 全量 `TEST_BATS_GHCR=1 make test-bats`（部署机等价 CI 环境）；
4. 交付物：验收报告（含镜像 digest、.env 键名清单、端点矩阵）。

## 4. 验收记录

验收记录按次归档在仓库外（报告文件），仓库内只留判据与复现命令——记录会过期，
命令不会。历史报告示例：《orgflow-devops-全新部署验收报告-2026-11-15》。
