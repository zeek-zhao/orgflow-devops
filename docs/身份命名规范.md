# 身份命名规范

> 状态：**已决策真本**（2026-11-05 起草，2026-11-06 转正，REQ-M0-A1/#84；§3 重命名映射的落地在 A2/#85 执行）
> 适用范围：`services/auth/ldif/*.ldif`、`out/dex/config.yaml`、Jenkins/Nexus LDAP 映射、`docs/`、`tests/bats/`
> 本文是「全量重命名」的唯一真源。迁移脚本、Issue、任务卡必须引用本文，不得另立映射表。

## 1. 为什么要改

现状 10 个 uid 表面上都是 `<givenName>.<sn>` 的小写形式，字符串格式其实统一；真正的问题是**语义**：把服务名和角色塞进了「人名」字段。

| 问题 | 证据 |
|---|---|
| 权限写在用户名里 | `gerrit.dev` / `nexus.dev` / `admin.jira` 等 uid，同时 `cn=*-admin` / `cn=*-dev` 组又重复表达一次权限 |
| 人账号与功能账号混在一起 | `zeek.zhao`（真人）与 `nexus.anonymous`（匿名访问占位）同级、同 objectClass |
| DN 不稳定 | DN 是 `cn=<显示名>,ou=users,...`，改一次显示名就要 modrdn；而 Dex / Jenkins 都按 `uid` 搜索，DN 与登录标识无关 |
| **uidNumber 冲突** | `admin.jira` 与 `dev.jira` 都是 `1009`（`services/auth/ldif/users.ldif`） |
| 注释与 DN 不一致 | `app.ldif` 里 `cn=jenkins-admin,ou=gerrit,...`、`cn=jira-admin,ou=gerrit,...` 两处注释写错（dn 行本身正确） |
| 头部注释失真 | `users.ldif` 写 `Total Entries: 9`，实际 10 个用户 + 1 个 OU |

方案 C（按服务拆 oauth2-proxy + 按组授权）要求「权限只由组表达」，因此用户名里不允许再出现服务名或角色。

## 2. 命名规则（强制）

### 2.1 uid

| 类别 | 格式 | 例子 | 说明 |
|---|---|---|---|
| 人账号 | `名.姓`，全小写 ASCII，仅一个 `.` | `zeek.zhao` | 只允许真实自然人。**禁止** `admin` / `dev` / `qa` / `anonymous` 等角色词充当名或姓 |
| 功能/服务账号 | `svc-<系统>-<用途>`，全小写，连字符分隔 | `svc-nexus-anonymous` | 给服务 bind、匿名映射、自动化任务用；**不供人登录** |
| 组 | `<系统>-<角色>` | `nexus-admin` | 权限的唯一载体；`memberUid` 引用 uid |

- uid 长度 ≤ 32，字符集 `[a-z0-9.-]`，不以 `.` 或 `-` 开头/结尾。
- 一个 uid 只能属于一个类别；改名必须同步改 §5 的全部引用点。
- **Git author 身份不受本规范约束**：`zeek.zhao <zeek.zhao@foxmail.com>` 是 `identity.yml` / `pre-push` / `pre-commit` / `Makefile identity-check` 的硬门禁，与 LDAP uid 同名只是巧合。迁移时**不得改动这些文件**。

### 2.2 DN 与属性

- 用户 DN 统一为 `uid=<uid>,ou=users,dc=devops,dc=com`，不再使用 `cn=<显示名>`。理由：Dex `userSearch.username=uid`、Jenkins `userSearch uid={0}`，DN 可直接由 uid 推导且不受显示名变更影响。
- 必填属性：`uid`、`cn`、`givenName`、`sn`、`displayName`、`mail`、`uidNumber`、`gidNumber`、`homeDirectory`、`loginShell`、`userPassword`。
- `mail` = `<uid>@devops.com`；`homeDirectory` = `/home/users/<uid>`。
- `uidNumber` **全局唯一**，从 1000 起连续分配；`gidNumber` 统一 501（权限不靠 gid）。
- `userPassword` 统一写成 **`{SSHA}` 哈希**（不再用无盐 `{MD5}`）；口令值统一为初始口令 **`123456`**，并在 `docs/账号与登录.md`、`orgflow-hosts.bat creds` 中明文写出以便交付。「明文」只体现在交付物上，LDIF 内不存明文。
- **不做 ppolicy 强制首登改密**（2026-11-05 决策，用户明确要求）。改密靠运维约定，不设目录级强制策略。

### 2.3 组与权限

- 权限**只能**通过 `cn=<系统>-<角色>,ou=<系统>,ou=groups,dc=devops,dc=com` 的 `posixGroup.memberUid` 表达。
- 禁止用 uid 前缀判断权限（例：不允许因为 uid 含 `admin` 就放行）。
- Dex `groupSearch.userMatchers` 已是 `userAttr: uid / groupAttr: memberUid`，映射表改完自动生效。
- Jenkins LDAP 插件默认 group membership filter `(|(member={0})(uniqueMember={0})(memberUid={1}))` 与 `posixGroup` 兼容，无需改 schema。

## 4. 迁移步骤（必须与 M1 认证改造同一个变更窗口）

1. 冻结登录，导出当前 LDAP 全量 LDIF 备份 + sha256 留档。
2. 改 `services/auth/ldif/users.ldif` / `app.ldif`：uid、DN、cn、mail、homeDirectory、uidNumber、memberUid、注释、头部 `Total Entries`。
3. 改 §5 清单的全部引用点。`out/dex/config.yaml` 是渲染产物，**只改 `scripts/render-dex.sh` / `services/auth/dex/` 真源**再重渲染。
4. `make down -v` 会重建 Caddy CA（所有客户端要重装根证书）。若不想触发，改用 `ldapmodify` 热迁移并在同窗口验证。
5. 逐服务验证：Dex 登录 → 各服务按组放行/拒绝 → Jenkins LDAP 登录 → Nexus LDAP 登录 → phpLDAPadmin 能显示新 DN。
6. 跑 `tests/bats/` 全量；`10_ldap.bats` 的 `33 条目` 与 `uid=admin.zeek` 断言必须同步更新。
7. 更新 `docs/账号与登录.md`、`docs/M0-测试体系.md`、`docs/task-cards/02-auth-stack.md`。

## 6. 验收判据

- `ldapsearch -b dc=devops,dc=com '(objectClass=*)' dn | grep -c '^dn:'` 迁移前后条目数一致（当前 33）；**禁止直接沿用旧数字，必须重算**。
- 无重复 `uidNumber`；所有 `memberUid` 都能解析到存在的 uid；所有 uid 符合 §2.1 规则。
- 每个用户 DN 形如 `uid=<uid>,ou=users,dc=devops,dc=com`。
- **核心验收**：用「非目标组成员」登录目标服务必须被拒，证明权限只由组决定（这是方案 C 的收口判据，也是本次重命名的根本目的）。

## 7. 回滚

保留迁移前全量 LDIF + 仓库 patch 备份；失败时 `ldapdelete` 新条目并重新 `ldapadd` 旧 LDIF，仓库引用用 `git revert` 回滚。
