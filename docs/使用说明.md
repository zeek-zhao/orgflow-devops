## 0. 从零开始：第一次部署的 30 分钟

> **读者**：拿到一台空机器、想让这套平台跑起来的新手。第 1 节讲的是「日常怎么用」，
> 这一节讲「第一次怎么把它立起来」。每一步的细节都在括号里的链接文档。

前提：一台 Linux 主机（Docker ≥ 26）、克隆本仓库、能访问 GHCR（镜像只拉不建）。

1. **装钩子**：`make hooks`（提交身份检查 + main 保护，见 [CONTRIBUTING](../CONTRIBUTING.md)）。
2. **配环境**：`cp .env.example .env`，填域名与端口。**所有账号口令只看这一份文件**：
   管理口令留空则首次 `deploy` 随机生成，写回 `.env`（不入库）；
   LDAP 用户初始口令来自 `ORGFLOW_INITIAL_PASSWORD`（`make ldap-apply` 会同步给各账号）。
3. **起全栈**：`USE_GHCR=1 make deploy` —— 校验镜像 pins → 拉 GHCR 锁定 digest → 起 10 个
   服务 → 逐个健康自检。若 images-guard 红了，是镜像上下文变了而 pins 没更新，走
   `make images-pin` 生成新 pins 并走 PR（见 [M0-镜像与CI](M0-镜像与CI.md)）。
4. **配客户端解析**：`make hosts` 生成 hosts 片段（或内网 dnsmasq），加到每台使用方机器
   （Windows 在 `C:\Windows\System32\drivers\etc\hosts`，需管理员）。
5. **信任内部 CA**：部署机 `make ca`；Windows 客户端双击 `out/ca/root.crt` 装进
   「受信任的根证书颁发机构」，并核对指纹一致（`down -v` 后 CA 会重新生成，所有客户端要重装）。
6. **初始化账号目录**：`docker compose exec -T ldap bash /opt/orgflow-auth/bootstrap-ldif.sh`
   （幂等）→ `make ldap-apply` 同步口令（详见 [services/ldap.md](services/ldap.md) 与
   [services/auth/README.md](../services/auth/README.md)）。
7. **推 Jenkins Job**：`make jobs`（16 个参数化 Job；JCasC 声明的配置不在此列）。
8. **起 Nexus**（特例，不在 compose 里）：Jenkins job `nexus-deploy`，或
   `bash scripts/nexus-deploy.sh`，幂等（见 [services/nexus.md](services/nexus.md)）。
9. **验收**：部署 ≠ 验证 —— 跑对应服务的 `verify-service` job；Windows 一键自检
   `tools/win-acceptance/Test-OrgflowAcceptance.ps1`；全栈 Bats 在 CI 跑（本地
   `make test-bats` 会起 DinD，生产机上慎用）。

做完这 9 步，回到第 1 节就是日常用法；坏了从第 5 节的排查入口进。

## 1. 入口与登录

所有站点都是 `https://<sub>.org-devops.com`，由 Caddy 统一承接（域名路由见 [ADR-13](ADR-13-域名路由.md)）。
**统一从入口面板进**，一屏看到所有服务：

| 入口 | 地址 | 是否要登录 |
|---|---|---|
| **统一入口面板** | `https://home.org-devops.com/` | 要（首页即看板） |
| Jenkins | `https://jenkins.org-devops.com/` | 要 |
| Nexus 制品库 | `https://nexus.org-devops.com/` | 要 |
| LDAP Admin | `https://ldapadmin.org-devops.com/` | 要 |
| 认证网关探活 | `https://auth.org-devops.com/ping` | 免（返回 `OK`） |
| Dex（OIDC） | `https://dex.org-devops.com/dex/` | 免（供其他服务跳转） |

**登录方式**：任何受保护站点未登录都会 302 到 `auth.org-devops.com`（OAuth2 Proxy），
再跳 Dex 的登录页。**账号在 LDAP 里**（初始账号见 [ldap.md](services/ldap.md)），
登录一次全站通行（cookie 共享）。初始口令由部署时生成、写在部署机的 `.env`（不入库）；
忘了密码就让目录管理员在 ldapadmin 里重置 `userPassword`。

管理员密码都在部署机的 `.env`（不入库，`deploy.sh` 首次运行随机生成）：
`JENKINS_ADMIN_PASSWORD` / `NEXUS_ADMIN_PASSWORD` / `LDAP_ADMIN_PASSWORD`。

**第一次用（或换了机器）**：

1. 让域名解析到部署机：把 `bash scripts/gen-hosts.sh <部署机IP>` 生成的行加进本机 hosts
   （Windows：`C:\Windows\System32\drivers\etc\hosts`，需管理员）。
2. 信任内部 CA：`bash scripts/ca-install.sh`（Linux/macOS）；Windows 双击
   `out/ca/root.crt` → 安装到「受信任的根证书颁发机构」。
   导入时务必确认根证书的指纹与 `out/ca/root.crt` 一致 —— 同名的旧根会让浏览器静默不信任。
   Firefox 用独立信任库，要单独导入。
3. 局域网 Windows 机器可一键自检：`tools/win-acceptance/Test-OrgflowAcceptance.ps1`
   （用法见 [win-acceptance](../tools/win-acceptance/README.md)）。

## 2. 部署一个服务

**日常走 Jenkins**（推荐，有审计、有参数、agent 上跑）：
`jenkins.org-devops.com` → job `deploy-service` → 选 SERVICE / ENV → Build。
部署完用 **`verify-service`** job 跑一次该服务的验收（部署 → healthy → 备份 → 断言三件套）。

**命令行等价**（213 上）：

```sh
cd ~/workbuddy/orgflow-devops
USE_GHCR=1 make deploy                                  # 全栈（首次 / 升级底座）
USE_GHCR=1 bash scripts/deploy.sh --service homepage    # 单服务
```

Nexus 特殊：**不在 compose 里**，由 `nexus-deploy` job（或 `bash scripts/nexus-deploy.sh`）
创建与改密，重跑幂等（[nexus.md](services/nexus.md)）。

判断「部署完是否真的好了」：`docker ps` 全 healthy 只是底线，跑 `verify-service` 才算验过
（`healthy ≠ 可用`：容器活着只说明进程没退，不代表反向代理通、登录能过）。

## 3. 备份与恢复

**备份**：Jenkins job `backup-service`（选 SERVICE / BACKUP_TARGET / RETENTION_DAYS），
或 213 上 `make backup`。产物在 `out/backups/`：`<svc>-<时间戳>.tgz` + `.sha256` + `.meta` 三件套，
按保留期自动清理。

**恢复**：Jenkins job `restore-service`（SERVICE / BACKUP_FILE / **CONFIRM=YES 才执行**），
或脚本 `bash scripts/restore.sh --service ldap --file <包> [--force]`。

恢复会**停服 → 清空卷 → 解包 → 启回**，所以：

- 目标卷非空必须 `--force`；CONFIRM=YES 就是让你想清楚再按
- 恢复前后都有闸门：sha256 校验、meta 服务/卷匹配、tar 条目安全检查
  （路径穿越 / 逃逸链接 / 设备节点一律拒绝——负向用例见 `tests/bats/33_restore_guards.bats`）
- 演练流程与周期见 [备份与恢复](备份与恢复.md)

## 4. 加一条路由（新站点）

1. 在 `config/routes.yaml` 加一条（subdomain / 上游 / 是否要登录 `auth: true`），
2. 走 PR + rebase 合并（流程见 [CONTRIBUTING](../CONTRIBUTING.md)），
3. `router` 容器 `--watch` 轮询到变更后渲染 Caddyfile 并 POST Caddy admin reload，
   **不需要**重启任何容器；`out/Caddyfile` 是渲染产物，别手改。
4. 验证：`curl -k --resolve <sub>.org-devops.com:443:127.0.0.1 https://<sub>.org-devops.com/ -I`
   （本机没 hosts 时用 `--resolve`，别依赖 DNS）。

## 5. 日常排查入口

| 现象 | 先看 |
|---|---|
| 某站点 502 / 000 | [网络架构](network/arch.md) 的分层排查决策树（IP 表 + 逐层打穿） |
| 某服务 unhealthy | [`services/<svc>.md`](services/) 的排查段（11 份，统一六段） |
| Jenkins job pending | [jenkins.md](services/jenkins.md) / [jenkins-agent.md](services/jenkins-agent.md)（healthy ≠ 能干活） |
| 证书告警 | 内部 CA 没信任，重装 `out/ca/root.crt`；`down -v` 之后 CA 会重新生成，**所有客户端要重装** |
| 登录循环 | [oauth2-proxy.md](services/oauth2-proxy.md)（它没有 API 旁路开关，API 校验走容器内直连） |
