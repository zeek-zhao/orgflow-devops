# 公网访问（Tailscale Funnel）

> 让公网用户通过一个 HTTPS 域名看到每个服务的状态与界面。配置标识 DOC-P-003。

## 入口

| 项 | 值 |
|---|---|
| 公网域名 | `https://orgflow-sandbox.tail0b7621.ts.net/` |
| 暴露方式 | `tailscale funnel --bg --yes 18080`（Funnel 在边缘终止 TLS） |
| 本地目标 | `127.0.0.1:18080`（公网网关 `scripts/public-gateway.py`） |
| 网关后端 | Docker 网桥 `192.168.90.0/24`，宿主机 `192.168.90.1` 直达容器，无需映射宿主端口 |

## 为什么需要网关

底座 7 服务使用内部域名（`*.org-devops.local`）与内部 CA 自签证书，公网无法解析。而 Funnel 只提供**一个** `*.ts.net` 域名。因此用一个轻量网关（标准库实现、无第三方依赖）把单一入口按路径反代到各容器，并提供汇总状态页。

## 路径映射

| 公网路径 | 后端 | 说明 |
|---|---|---|
| `/` | 网关自身 | 服务总览（实时健康 + 快捷链接） |
| `/api/health` | 网关自身 | JSON 健康清单（可监控） |
| `/home/` | `homepage:3000` | 统一导航面板 |
| `/ldapadmin/` | `ldapadmin:8080` | LDAP 管理页 |
| `/router/` | `router:8080` | 路由状态/热更新 |
| `/caddy/` | `caddy:2019` | 反向代理 admin（只读查看） |
| `/healthz` | 网关自身 | 网关存活探针 |

`ldap`(389) 与 `dnsmasq`(53/udp) 非 HTTP，只在总览页展示健康状态，不提供 Web 路径。

## 运维命令

```bash
# 启动网关（宿主机，后台）
GW_PORT=18080 setsid python3 scripts/public-gateway.py >/tmp/gw.log 2>&1 </dev/null &
# 开启/关闭公网暴露
tailscale funnel --bg --yes 18080
tailscale funnel --https=443 off
# 自检
curl -s https://orgflow-sandbox.tail0b7621.ts.net/api/health
```

## 当前限制（重要）

公网服务当前依赖**本地 overlay 挂载修复文件**启动，因为 digest 锁定的旧镜像存在构建缺陷：

| 服务 | 旧镜像缺陷 | 修复 |
|---|---|---|
| ldap | 缺 `bootstrap.ldif.tmpl`、初始化判断错误、临时 slapd daemonize 占 389、缺 `moduleload back_mdb` | 已修源码，待 CI 重建镜像 |
| caddy | 未安装 caddy 本体（`exec: caddy: not found`） | 已修 Dockerfile（cloudsmith 源），待 CI 重建 |
| router | 缺 `python3-yaml`（`/render` `/routes` 报 422） | 已修 Dockerfile，待 CI 重建 |

**持久化前提**：PR #192 合并 → CI 重建这 3 个镜像 → 回填 `config/images.env` 与 `tests/images.lock` 的新 digest → 重新拉取镜像 → 用纯 `docker compose`（无 overlay）重启全栈 → 重启网关与 Funnel。在此之前，服务可用但重建容器会丢失 overlay 修复。

另：`config/defaults.env` 中 `IP_*` 为容器固定 IP，网关据此直达；如改网段需同步网关（改后重启网关进程即可，无需重启服务）。
