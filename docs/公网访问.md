# 公网访问（Tailscale Funnel + Caddy 唯一入口）

> 让公网用户通过一个 HTTPS 域名直接访问所有服务。配置标识 DOC-P-003。

## 设计原则

底座的**唯一 Web 入口是 Caddy**。公网不额外引入旁路网关，所有服务流量都经 Caddy 反代：

```
公网用户
   │ HTTPS（*.ts.net 合法证书）
   ▼
Tailscale Funnel（边缘终止 TLS）
   │ 明文 HTTP → 127.0.0.1:18081
   ▼
Caddy :18081（公网入口，按 path 路由）
   ├── /home/*       → homepage:3000
   ├── /ldapadmin/*  → ldapadmin:8080
   ├── /router/*     → router:8080
   ├── /caddy/*      → caddy:2019（admin 只读）
   └── /  /healthz   → Caddy 自身（总览页 / 存活探针）
```

底座 7 服务使用内部域名（`*.org-devops.local`）+ 内部 CA 自签证书，公网无法解析；而 Funnel 只提供**一个** `*.ts.net` 域名。Caddy 的公网入口站点（`:18081`，纯 HTTP，因 TLS 已在 Funnel 边缘终止）按 path 分发，是唯一需要新增的配置。

## 入口

| 项 | 值 |
|---|---|
| 公网域名 | `https://orgflow-sandbox.tail0b7621.ts.net/` |
| 暴露方式 | `tailscale funnel --bg --yes 18081`（Funnel 边缘终止 TLS） |
| 本地目标 | `127.0.0.1:18081`（Caddy 公网入口，宿主端口映射 `${PUBLIC_PORT:-18081}:18081`） |
| 配置真源 | `services/caddy/entrypoint.sh` 生成的 Caddyfile（公网站点块） |

## 路径映射（全部经 Caddy）

| 公网路径 | 后端 | 说明 |
|---|---|---|
| `/` | Caddy | 服务总览（静态列表 + 快捷链接） |
| `/healthz` | Caddy | 入口存活探针 |
| `/home/` | `homepage:3000` | 统一导航面板 |
| `/ldapadmin/` | `ldapadmin:8080` | LDAP 管理页 |
| `/router/` | `router:8080` | 路由状态/热更新 |
| `/caddy/` | `caddy:2019` | 反向代理 admin（只读查看） |

`ldap`(389) 与 `dnsmasq`(53/udp) 非 HTTP 内部服务，不提供公网 Web 路径。

> 修复记录：原内网站点 `reverse_proxy home:3000` 指向了不存在的服务名 `home`（compose 服务名实为 `homepage`），导致 `home.org-devops.local` 一直 502。已在 entrypoint 中改为 `homepage:3000`。

## 运维命令

```bash
# 开启/关闭公网暴露（指向 Caddy 公网入口）
tailscale funnel --bg --yes 18081
tailscale funnel --https=443 off
# 自检
curl -s https://orgflow-sandbox.tail0b7621.ts.net/healthz
curl -s https://orgflow-sandbox.tail0b7621.ts.net/home/
```

Funnel 是**进程级后台服务**：机器或 tailscaled 重启后需重跑 `tailscale funnel --bg --yes 18081`（可用 cron `@reboot` 或 systemd unit 固化，见交付说明）。
