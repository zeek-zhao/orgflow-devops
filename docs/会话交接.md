## 1. 这个工程是什么

### 1.1 定位

单仓（`zeek-zhao/orgflow-devops`，**私有**）。以 Jenkins 为唯一编排入口，自举出「权限管理 + 路由注册 + Caddy + Nexus + 备份」这一套底座，各服务的部署/备份由**参数化 Jenkins Job** 驱动。

需求真本在 vault：`40-项目/orgflow-devops/orgflow-devops-需求方案.md`（v0.2.0）。仓库内不含该文档。

### 1.2 四层结构

```
用户 → Caddy（TLS 站点）→ OAuth2 Proxy（认证）→ 各服务          # 数据面
config/routes.yaml → router（render.py）→ Caddy admin /load      # 控制面
Jenkins deploy-service / backup-service / restore-service        # 运维面
dnsmasq（容器内 DNS）+ 宿主/局域网 hosts 片段                     # 名字解析面
```

关键设计取向：**`config/routes.yaml` 是路由的唯一真源**，没有任何第二处配路由的地方。改完不用重启，`router` 容器在 watch 这个文件。

### 1.3 域名模型（ADR-13）

每个服务一个独立站点 `https://<subdomain>.<GATEWAY_DOMAIN>`，`GATEWAY_DOMAIN` 默认 `org-devops.com`。全部用 Caddy 内部 CA（`local_certs`），**不向公网申请证书**。

| 站点 | 服务 | 需要登录 |
|---|---|---|
| `home.<domain>` | homepage（统一入口，从这进） | 否 |
| `jenkins.<domain>` | Jenkins | **是** |
| `nexus.<domain>` | Nexus | 否 |
| `ldapadmin.<domain>` | LDAP Admin | 否 ← **M0 遗留项，上生产前必须加鉴权** |
| `dex.<domain>` | Dex | 否 |
| `auth.<domain>` | OAuth2 Proxy | — |

**路径式入口（`http://localhost:8080/jenkins` 这类）已彻底删除**，ADR-13 之后不再支持。

⚠️ 认证域名**只由 `config/routes.yaml` 里 `name: auth` 那条路由的 `subdomain` 决定**。没有 `AUTH_SUBDOMAIN` 这个变量，别去找。

### 1.7 CI 四条流水线

| 文件 | 触发 | 干什么 |
|---|---|---|
| `identity.yml` | PR（opened/synchronize/reopened/ready_for_review）+ push main | 校验 author（PR 上还有 committer）、**拦截 `Co-authored-by` / AI 署名** |
| `test.yml` | push main + PR + 手动 | `make identity-check` → `make test`（81 用例）→ **`ALLOW_PULL_DOCKER_HUB=1 make test-bats`（DinD 跑 13/23）** |
| `images.yml` | 仅在 `tests/harness/**` `services/router/**` `services/dnsmasq/**` `tools/jjb/**` 变更时 + 手动 | 构建 4 个自建镜像推 GHCR，`digests` job 汇总 digest 作为 artifact |
| `mirror.yml` | 每周一 03:00 + 手动 | 把 9 个上游镜像同步成 `mirror-*`。`mode=all` 保留上游 digest（`docker-compose.ghcr.yml` 钉的就是它），**`amd64` 会破坏这些钉死值** |

### 3.1 三个值得单独说的

#### #29：`refusing to create a tag with a digest reference`

**现象**：213 上 `USE_GHCR=1 make deploy` 直接失败。

**根因**：GHCR 覆盖层把 `image:` 钉成 `repo:tag@sha256:...`。compose 看到某服务同时有 `build:` 和 digest 形式的 `image:`，就去构建，并把 digest 当 tag 写 → 报错。有 `build:` 的是 **`dnsmasq` / `router` / `jjb`** 三个。

**修法**：构建标志必须跟镜像来源走，不能写死 `--build`：

```bash
if [ "${USE_GHCR:-0}" = 1 ]; then BUILD_FLAG="--no-build"; else BUILD_FLAG="--build"; fi
```

`Makefile` 的 `deploy` 目标透传 `USE_GHCR`。

**为什么 CI 抓不到**（重要，别再踩）：CI 的 harness 是 `compose up -d --no-build --pull never` **直连**，`make up` 自带 `--no-build`，**只有 `make deploy` 走 `deploy.sh` 的 `--build`** —— 这条路径零覆盖。以后改 `deploy.sh` 必须去真机验。

**踩过一次的坑**：修 #29 时顺手把 `$BUILD_FLAG` 也塞进了 `--service` 分支，把 `test_jobs.py::test_deploy_selected_service_and_version` 打红了（它断言精确参数）。`--service` 原本语义是「缺镜像才构建」，不该强制。最终只收窄到 `USE_GHCR=1` 时加 `--no-build`，默认路径一字不动。

#### #32：验收清单真机勾选

11 条验收逐条在 213 上跑：**8 通过 / 1 阻塞（#30）/ 1 需人工（局域网 oauth2 登录）/ 1 由 CI 覆盖**。顺带修了 5 处计数漂移（12→13 包、7→8 镜像、5→6 路由、76→81 用例、12/21→13/23）。

**顺手学到的一条**：验收脚本自己也会有 bug。当时 `echo "conn-fail"` 和 curl 的 `000` 拼成了 `000conn-fail`，导致「旧入口已消失」误判 FAIL。单独复核才确认：`of-caddy` 只发布 `0.0.0.0:80`/`443`，直连 8080 curl 退出码 **7**，旧入口确实没了。

#### #19：Homepage 的 `HOMEPAGE_ALLOWED_HOSTS`

精确匹配 Host 头，**含端口**。必须两种写法都列：

```
home.org-devops.com,home.org-devops.com:443
```

健康检查用 `node` 而不是 wget/curl（那个镜像里不一定有，但 node 一定在），判据是 `<500` 而不是 `==200` —— 探针从 `127.0.0.1` 发，Host 头不在白名单里，正常返回 **400**，而那个 400 恰好证明 HTTP 是活的。

## 4. 未解决的问题

### 4.1 #30 —— 唯一 open 的 Issue

**`make jobs` 在域名路由后推不进 Jenkins。**

两个**互相独立**的阻塞，必须都解决：

#### 阻塞 A：宿主不解析 `<sub>.<domain>`

`jjb` 服务是 `network_mode: host`，用的是**宿主解析器**，容器内的 dnsmasq 帮不上忙。而 `make hosts` 生成的 hosts 片段没有装到宿主。

报错原文：

```
NameResolutionError("... Failed to resolve 'jenkins.org-devops.com' ([Errno -2] ...)")
```

#### 阻塞 B：即使解析成功，API 也被 oauth2 拦

```
curl -u admin:$PW https://jenkins.org-devops.com/api/json  → 302
```

**没有旁路可用**，已逐项排除：

- oauth2-proxy **没有** `--skip-jwt-bearer-tokens`
- oauth2-proxy **没有** `--skip-auth-route`
- Jenkins API token 是 **Basic 认证，不是 JWT** —— 所以即使有前者也救不了

#### 推荐方案 A

**把 `jjb` 去掉 host 网络，改走 compose 内网 `http://jenkins:8080`。**

- 一次解决两个阻塞：不依赖宿主 DNS，也不经过 oauth2
- **不放宽任何鉴权**
- 代价：`jjb` 要能拿到 `JENKINS_ADMIN_PASSWORD`（compose 内网直连仍需 Basic 认证）

**方案 B（不推荐）**：给 `jenkins.<domain>` 的 `api/json` 加 `--skip-auth-route` 例外。等于在统一认证上开口子，而且 Basic 认证也不走 JWT，实现起来更绕。

#### 怎么复现（213 上）

```bash
cd ~/workbuddy/orgflow-devops
make jobs                      # 期望：NameResolutionError
# 证明阻塞 A：宿主确实不解析
getent hosts jenkins.org-devops.com || echo "宿主不解析 ← 阻塞 A 成立"
# 证明阻塞 B：即使绕过 DNS 也进不去
curl -sk -o /dev/null -w '%{http_code}\n' \
  --resolve jenkins.org-devops.com:443:127.0.0.1 \
  -u "admin:$(grep '^JENKINS_ADMIN_PASSWORD=' .env | cut -d= -f2)" \
  https://jenkins.org-devops.com/api/json      # 期望：302 ← 阻塞 B 成立
# 反证：compose 内网是通的（方案 A 的前提）
# 期望 403/200 而不是 "unable to connect"——403 就够证明网络通，只是没带认证
docker compose exec caddy wget -qO- http://jenkins:8080/api/json 2>&1 | head -3
```

> `make jobs` 在 `Makefile` 里依赖 `out/ca/root.crt`（`jobs: out/ca/root.crt`），改之前先看清这条依赖链——方案 A 走 http 内网之后，这个 CA 依赖大概率可以去掉。

| 3 | **author 恒为 `zeek.zhao <zeek.zhao@foxmail.com>`** | `pre-commit` + `pre-push` + `identity.yml` + `make identity-check` | push 被拒 / CI 红 |
| 4 | **提交消息不能有 `Co-authored-by` / `Signed-off-by` / AI 署名** | `commit-msg` 钩子 + `identity.yml`（含 `🤖`） | 提交被拒 / CI 红 |
| 5 | **`.env` 不入库** | `.gitignore` | 泄露凭据 |
| 6 | **不改 `tests/images.lock`** | 流程 | digest 漂移，`18_public` 会红 |

**三个绕过变量**（都存在，但只给历史迁移用，别常态化）：`WF4_ALLOW_PUSH_MAIN=1`（跳过主干保护）、`GIT_IDENTITY_ALLOW=1`（跳过身份校验）、`GIT_MSG_ALLOW=1`（跳过消息校验）。

**检查范围不一样，别搞混**：

- `pre-push` 只查**本次推送真正新增**的提交（新分支 = `main..HEAD`），不扫全量历史
- `make identity-check` 扫**全量历史**（`git log --no-merges --format='%ae'`）

所以「push 过了」不等于「`make identity-check` 会过」。

私有库的 branch protection / rulesets **一律 403**（`Upgrade to GitHub Pro`），本地钩子是唯一防线。另外：**这个仓库不要转公开**，里面有内网 IP。

### 5.1 Squash 为什么是硬伤（已踩过一次）

squash 提交只有**单父**，`identity-check` 的 `--no-merges` **滤不掉它**，于是全历史扫描直接把 author 是账号 noreply 邮箱的提交判红：

```
✗ author 异常: 42319166+zeek-zhao@users.noreply.github.com
```

PR #25 就是被 squash 合并的，事后用 `--amend --author` + `--force-with-lease` 修回：`4c27bd3` → `81039e1`，`git diff 4c27bd3 81039e1` 为空（树零变化，只改了 author）。

> 新克隆里 `4c27bd3` 已不可达，只能看到 `81039e1`。这段历史细节记在 `docs/提交规范.md` §5「历史重写记录」。

**Rebase 合并后的提交在脚本层面和 squash 提交无法区分**，所以这条只能靠流程。用 API 合并时显式传 `merge_method=rebase`，用网页时点「Rebase and merge」。

### 5.2 提交身份

```bash

git config user.email "zeek.zhao@foxmail.com"
```

main 上的 committer 允许是 `GitHub <noreply@github.com>`（平台生成，改不了）；分支上的 committer 也必须是本人。

## 6. 环境陷阱速查

每一条都是实际踩过的。**表里「怎么确认」那列可以直接跑。**

### 6.1 Windows 侧跑测试

| 陷阱 | 现象 | 怎么处理 |
|---|---|---|
| `make` 不存在 | `make: command not found` | 用等价 bash 复刻，或进 WSL |
| `test_deploy.py` 在 Windows 跑不了 | `Compose 配置解析失败` / `UnicodeDecodeError 0x95` | mock 的 shebang 是 Windows 路径，Git Bash 执行不了 → **拷进 WSL 跑** |
| WSL 里 `set: pipefail: invalid option name` | 多个套件连环红 | 工作区 `.sh` 有 **CRLF 遗留** → `find . -name '*.sh' -exec sed -i 's/\r$//' {} +` |

拷进 WSL 的正确姿势：

```bash
tar --exclude=.git -cf - . | (cd /tmp/orgflow-devops && tar xf -)
cd /tmp/orgflow-devops && find . -name '*.sh' -exec sed -i 's/\r$//' {} +
python3 scripts/test_deploy.py
```

> ⚠️ **必须 `--exclude=.git`**。带了 `.git` 之后，副本看起来就是个正常仓库，在里面手滑跑一句 `git checkout -- .` 就会把**未提交的改动**全回滚掉（踩过一次，改动重做了一遍）。不带 `.git` 时任何 git 命令都直接报「not a repository」，反而是保护。

### 6.2 SSH 的两个坑

| 陷阱 | 现象 | 正确做法 |
|---|---|---|
| `ssh -n host 'bash -s' < script` | **静默无输出**，脚本根本没送过去 | `-n` 把 stdin 换成 `/dev/null` → **去掉 `-n`** |
| `ssh host '...' \| head -40` | 远端脚本执行到第 40 行就被掐断，后续步骤静默不执行 | `head` 关闭管道 → SIGPIPE。**结果先落文件再整段取回** |

> 踩过一次：以为 `.env` 断言失败（两项没打印），实际是脚本被 `head` 杀在半路。

### 6.3 部署与路由

| 陷阱 | 现象 | 怎么确认 |
|---|---|---|
| `USE_GHCR=1` 时用 `--build` | `refusing to create a tag with a digest reference` | 见 §3.1；`docker-compose.yml` 里有 `build:` 的是 dnsmasq / router / jjb |
| 以为宿主 `make render` 会热加载 | 改了 `routes.yaml` 站点没变 | **真机制是 `router` 容器的 `--watch`**（轮询文件 + POST `/load`）。Caddy admin 只在容器网络（`caddy:2019`），宿主够不到 |
| 历史重写后旧克隆分叉 | `git pull` 不退化为快进，报 `ahead N, behind M` | `git fetch && git reset --hard origin/main` |
| 旧格式 `.env` 部署失败 | 缺端口变量 / 硬编码 `JENKINS_URL` | 补 `GATEWAY_HTTP_PORT` / `GATEWAY_HTTPS_PORT`，`JENKINS_URL` 改成域名式。`GATEWAY_PORT` / `LDAPADMIN_PORT` / `ROUTER_PORT` 已无引用，可删 |
| 想用旧参数改端口/域名 | `deploy.sh` 直接报「已废弃」并退出 | `SERVICE_PORT` / `SERVICE_DOMAIN` 已被 ADR-13 废弃，改 `.env` 的 `GATEWAY_HTTP_PORT` / `GATEWAY_HTTPS_PORT` / `GATEWAY_DOMAIN` |
| `curl --resolve` 不生效 | 请求打到真实 DNS 上去了 | `--resolve HOST:PORT:ADDR` **按 host:port 精确匹配**。URL 不带端口就是隐式 443，映射必须写 `:443` |
| 测试忘了 `https://` | 站点匹配不上 | 一律带 `https://`，且**不要加 `-L`** |
| 拿证书 CN 去断言域名 | 永远找不到 | Caddy 叶子证书**无 CN**，域名只在 SAN 里 |

### 6.4 认证栈

| 陷阱 | 现象 | 正确做法 |
|---|---|---|
| dex 整目录挂载 | `chdir EACCES`，报成 `gomplate: permission denied` | dex 容器 uid 1001 → **只能单文件挂载**，渲染后 `chmod 0644` |
| dex 端点路径 | 404 | 端点仍在 `/dex/*`，**不剥前缀** |
| gethomepage 配置挂载 | 启动即挂 | 配置挂 `/app/config`，**不能加 `:ro`** |
| oauth2-proxy 想加 API 旁路 | 找不到开关 | **没有** `--skip-jwt-bearer-tokens`，**没有** `--skip-auth-route` |
