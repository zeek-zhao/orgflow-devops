## 1. 这个工程是什么

### 1.1 定位

单仓（`zeek-zhao/orgflow-devops`，**私有**）。以 Jenkins 为唯一编排入口，自举出
「权限管理 + 路由注册 + Caddy + Nexus + 备份」这一套底座，各服务的部署/备份由
**参数化 Jenkins Job** 驱动。

需求真本在 vault（`40-项目/orgflow-devops/orgflow-devops-需求方案.md`），仓库内不含该文档。
**除此之外的一切（设计、验收、待办、踩坑）都在本仓库 `docs/` 里，不需要外部资料。**

### 1.2 四层结构

```
用户 → Caddy（TLS 站点）→ OAuth2 Proxy（认证）→ 各服务          # 数据面
config/routes.yaml → router（render.py）→ Caddy admin /load      # 控制面
Jenkins deploy-service / backup-service / restore-service        # 运维面
dnsmasq（容器内 DNS）+ 宿主/局域网 hosts 片段                     # 名字解析面
```

关键设计取向：**`config/routes.yaml` 是路由的唯一真源**，没有任何第二处配路由的地方。
改完不用重启，`router` 容器在 watch 这个文件。

### 1.3 域名模型（[ADR-13](ADR-13-域名路由.md)）

每个服务一个独立站点 `https://<subdomain>.<GATEWAY_DOMAIN>`，`GATEWAY_DOMAIN` 默认
`org-devops.com`。全部用 Caddy 内部 CA（`local_certs`），**不向公网申请证书**。

| 站点 | 服务 | 需要登录 | 期望状态码 |
|---|---|---|---|
| `home.<domain>` | homepage（统一入口，从这进） | 否 | 200 |
| `jenkins.<domain>` | Jenkins | **是** | 302 |
| `nexus.<domain>` | Nexus | 否 | 200（job 起之前是 502） |
| `ldapadmin.<domain>` | LDAP Admin | **是** | 302 |
| `dex.<domain>` | Dex | 否 | `/dex/healthz` 200 |
| `auth.<domain>` | OAuth2 Proxy | — | 302 |

**路径式入口（`http://localhost:8080/jenkins` 这类）已彻底删除**，ADR-13 之后不再支持。

⚠️ 认证域名**只由 `config/routes.yaml` 里 `name: auth` 那条路由的 `subdomain` 决定**。
没有 `AUTH_SUBDOMAIN` 这个变量，别去找。

⚠️ **Dex 没有根 handler**：`/`、`/dex`、`/dex/` 全是 404，真入口是 `/dex/auth`。
判活用 `/dex/healthz`。拿 `/` 判会得出「dex 挂了」的错误结论。

### 1.7 CI 四条流水线

| 文件 | 触发 | 干什么 |
|---|---|---|
| `identity.yml` | PR + push main | 校验 author（PR 上还有 committer）、**拦截 `Co-authored-by` / AI 署名** |
| `test.yml` | push main + PR + 手动 | `make identity-check` → `make test` → `ALLOW_PULL_DOCKER_HUB=1 make test-bats`（DinD） |
| `images.yml` | `services/**` `tools/**` `tests/harness/**` `.github/scripts/**` 变更 + 手动 | **按改动裁剪**后构建自建镜像推 GHCR |
| `mirror.yml` | 每周一 03:00 + 手动 | 同步 8 个上游镜像成 `mirror-*`。`mode=all` 保留上游 digest，**`amd64` 会破坏钉死值** |

**`images.yml` 不是全量构建**：`.github/scripts/select-images.sh` 按改动路径算出要建哪几个，
只改 `tools/jenkins-agent/**` 就只建 `jenkins-agent`。改动落在 `.github/**`、
`workflow_dispatch`、新建分支、或 `git diff` 算不出来时，退化为全量（宁可多建，不可漏建）。
详见 [镜像与 CI](M0-镜像与CI.md)。

**`test.yml` 的 DinD 刻意不做路径跳过** —— 它是这套栈唯一的自动化真验证，按路径跳过是假绿。

### 3.2 Squash 为什么是硬伤（已踩过一次）

squash 提交只有**单父**，`identity-check` 的 `--no-merges` **滤不掉它**，于是全历史扫描
直接把 author 是账号 noreply 邮箱的提交判红：

```

```

PR #25 就是被 squash 合并的，事后用 `--amend --author` + `--force-with-lease` 修回
（树零变化，只改了 author）。**Rebase 合并后的提交在脚本层面和 squash 提交无法区分**，
所以这条只能靠流程：用 API 合并时显式传 `merge_method=rebase`，用网页时点「Rebase and merge」。

## 4. 陷阱速查

每一条都是实际踩过的。**表里「怎么处理」那列可以直接照做。**

### 4.1 容器与权限

> 这一组是 2026-11-01 真机验收暴露的，三条都属于「机器全绿、一上真机就挂」，
> 而且**报错文案指向的地方全都不是真因**。完整复盘见
> [M0 验收记录 §12](M0-验收记录.md#十二验收过程暴露的缺陷核心复盘)。

| 陷阱 | 现象 | 正确做法 |
|---|---|---|
| **agent 的 SSH 用户是 `jenkins(1000)` 不是 root** | job 报「找不到网络 orgflow」，而网络明明在 | 上游 `jenkins/ssh-agent` 镜像 `PermitRootLogin no`。`/var/run/docker.sock` 是 `root:<docker 组> 0660`，必须让 uid 1000 进那个组 |
| **`group_add` 到不了 SSH 会话** | `docker exec -u jenkins ... docker info` 一路绿灯，但 job 里照样 permission denied | `docker exec` 继承 OCI spec 的 `AdditionalGids`，而 sshd 登录会话会 `initgroups()` **按 `/etc/group` 重置**。必须在 entrypoint 里改 `/etc/group`。**判据必须用 `su -s /bin/sh -c '...' jenkins`，不能用 `docker exec -u`** |
| **docker 组只能用数字 gid** | 按组名 `usermod -aG docker` 在容器里找不到组 | 容器内 `/etc/group` 与宿主对不上（213 宿主 998 叫 `docker`，容器内叫 `systemd-network`）。用 `DOCKER_GID`（`stat -c %g /var/run/docker.sock`） |
| **agent 的 sshd host key 每次重建都变** | 节点 offline，页面等一个「Trust SSH Host Key」的点击，没人会点 | `manuallyTrustedKeyVerificationStrategy` 记的是**第一次见到的 key**。正解：host key 做成受管产物（`secrets/agent_host_key` 挂 `/etc/ssh/ssh_host_ed25519_key:ro`）+ JCasC 用 `manuallyProvidedKeyVerificationStrategy` |
| **`ManuallyProvidedKeyVerificationStrategy` 构造时就 `parseKey`** | 空串会让 JCasC 整份配置失败，Jenkins 直接起不来 | 三处入口（`deploy.sh` / harness / `Makefile`）都必须 export，且 `.pub` 要切成「算法 base64」两列（第三列是注释） |
| **`ssh-slaves` 的类不在外层 `.jpi` 里** | 直接 `grep` 插件包永远 0 命中，会误判成「插件不支持」 | 类在 `WEB-INF/lib/ssh-slaves.jar` 嵌套 jar 里。要么 `unzip -p` 抽内层，要么查文档 |
| **容器 healthy ≠ 服务可用** | 10 容器全 healthy，job 全 pending | healthy 只证明 sshd / 进程在听。必须有一条**打穿全链路的真实 job**（`nexus-deploy`），且要在**重建容器之后**再跑一遍 |

### 4.2 Windows 侧跑测试

| 陷阱 | 现象 | 怎么处理 |
|---|---|---|
| `make` 不存在 | `make: command not found` | 用等价 bash 复刻，或进 WSL |
| `test_deploy.py` 在 Windows 跑不了 | `Compose 配置解析失败` / `UnicodeDecodeError 0x95` / 直接超时 | mock 的 shebang 是 Windows 路径，Git Bash 执行不了 → **拷进 WSL 跑**，或依赖 CI |
| `python3 → subprocess.run(["bash", ...])` 挂死 | 无输出、进程不退出 | `sh` 正常、`bash` 挂死。给 `subprocess.run` 打垫片把 `bash` 换成 `sh` |
| WSL 里 `set: pipefail: invalid option name` | 多个套件连环红 | 工作区 `.sh` 有 **CRLF 遗留** → `find . -name '*.sh' -exec sed -i 's/\r$//' {} +` |
| PowerShell 5.1 没有 `System.Net.Http` | `New-Object System.Net.Http.HttpClientHandler` 报「找不到类型」 | 别用 HttpClient；用 `HttpWebRequest` 或 `SslStream` |
| PS 5.1 里 ScriptBlock 委托跨线程 | 「此线程中没有可用于运行脚本的运行空间」，而报错被包装成「根证书没导入？」 | 回调必须在**同线程同步**执行（`SslStream.AuthenticateAsClient`），不要给 `HttpClient` 挂委托 |

拷进 WSL 的正确姿势：

```sh
tar --exclude=.git -cf - . | (cd /tmp/orgflow-devops && tar xf -)
cd /tmp/orgflow-devops && find . -name '*.sh' -exec sed -i 's/\r$//' {} +
python3 scripts/test_deploy.py
```

> ⚠️ **必须 `--exclude=.git`**。带了 `.git` 之后副本看起来就是个正常仓库，
> 在里面手滑跑一句 `git checkout -- .` 就会把**未提交的改动**全回滚掉（踩过一次）。
> 不带 `.git` 时任何 git 命令都直接报「not a repository」，反而是保护。

### 4.3 SSH

| 陷阱 | 现象 | 正确做法 |
|---|---|---|
| `ssh -n host 'bash -s' < script` | **静默无输出**，脚本根本没送过去 | `-n` 把 stdin 换成 `/dev/null` → **去掉 `-n`** |
| `ssh host '...' \| head -40` | 远端脚本执行到第 40 行就被掐断，后续步骤静默不执行 | `head` 关闭管道 → SIGPIPE。**结果先落文件再整段取回** |
| `ssh host 'python3 -c "..."'` | 远端 zsh 下极易 parse error | **写成 `.py` 文件 scp 过去**，不要塞进一行引号里 |

### 4.4 部署与路由

| 陷阱 | 现象 | 怎么确认 / 处理 |
|---|---|---|
| `USE_GHCR=1` 时用 `--build` | `refusing to create a tag with a digest reference` | 镜像钉了 digest 就不能 build。`docker-compose.yml` 里有 `build:` 的是 dnsmasq / router / jjb / jenkins / jenkins-agent |
| 以为宿主 `make render` 会热加载 | 改了 `routes.yaml` 站点没变 | 真机制是 `router` 容器的 `--watch`（轮询 + POST `/load`）。Caddy admin 只在容器网络（`caddy:2019`），宿主够不到 |
| `make deploy SERVICE=xxx` 不重建容器 | 改了 bind mount 配置没生效 | compose 认为无变化就跳过。必须 `docker compose --env-file .env restart <svc>` |
| `make down -v` 删不掉卷 | 只打印 GNU Make 版本号 | `-v` 被 make 当成 `--version` 吃掉了。要删卷直接 `docker compose --env-file .env down -v` |
| 历史重写后旧克隆分叉 | `git pull` 不退化为快进，报 `ahead N, behind M` | `git fetch && git reset --hard origin/main` |
| `curl --resolve` 不生效 | 请求打到真实 DNS 上去了 | `--resolve HOST:PORT:ADDR` **按 host:port 精确匹配**。URL 不带端口就是隐式 443，映射必须写 `:443` |
| `curl` 的 URL 里有 `[...]` | `curl: (3) bad range in URL`，body 为空 | 加 `-g`（关 glob）。`?tree=computer[...]` 这类 API 必踩 |
| 测试忘了 `https://` | 站点匹配不上 | 一律带 `https://`，且**不要加 `-L`** |
| 拿证书 CN 去断言域名 | 永远找不到 | Caddy 叶子证书**无 CN**，域名只在 SAN 里 |
| 从 213 直接 curl 域名得到 `000` | 看起来像服务挂了 | 213 的 `/etc/hosts` 可能缺这条（见 [待办](待办.md)）。用 `--resolve` 绕过，或先 `make hosts` |
| `down -v` 之后证书全失效 | 复测全 `000` | `caddy_data` 卷被删 → Caddy 重新生成 CA → 之前导出的根证书立即作废，所有客户端要重装 |

### 4.5 认证栈

| 陷阱 | 现象 | 正确做法 |
|---|---|---|
| dex 整目录挂载 | `chdir EACCES`，报成 `gomplate: permission denied` | dex 容器 uid 1001 → **只能单文件挂载**，渲染后 `chmod 0644` |
| dex 端点路径 | 404 | 端点仍在 `/dex/*`，**不剥前缀**。判活打 `/dex/healthz` |
| gethomepage 配置挂载 | 启动即挂 | 配置挂 `/app/config`，**不能加 `:ro`** |
| oauth2-proxy 想加 API 旁路 | 找不到开关 | **没有** `--skip-jwt-bearer-tokens`，**没有** `--skip-auth-route` |
| oauth2 站点被 forward_auth 包住 | 带 basic auth 打 `jenkins.<domain>` 只得到 302，请求到不了 Jenkins | API 校验走 `docker exec of-jenkins curl 127.0.0.1:8080`，不要打域名 |

### 4.6 流程与 AI 协作

| 陷阱 | 现象 | 正确做法 |
|---|---|---|
| **`gh pr merge --squash`**（2026-11-03 踩过） | 合并成功，但 squash 提交单父，`identity-check` 的 `--no-merges` 滤不掉 → author 是账号 noreply 邮箱，**全历史扫描直接红** | 合并一律 **`gh pr merge --rebase`**。已踩的修复：`git rebase <基点> --exec 'git commit --amend --no-edit --author="zeek.zhao <zeek.zhao@foxmail.com>"'`（树零变化），`WF4_ALLOW_PUSH_MAIN=1 git push --force-with-lease origin main`，再 `make identity-check` 复核 |
| `gh pr merge` 不带方式参数 | GitHub 交互提示，AI 侧容易误选 squash | 脚本里**显式传** `--rebase`，与 §3.2 一致 |
| 检出别人的 PR 分支后直接改文件 | 工作区改动被 checkout/reset 冲掉 | **先建分支、再改文件**；或先 `git stash`（验收记录 §12 的事故） |

```sh
# --- 本机（Windows 侧可用的）---
git log --oneline -5
curl -s -g -H "Authorization: Bearer $(cat ~/.config/wb/github.token)" \
  "https://api.github.com/repos/zeek-zhao/orgflow-devops/issues?state=open"   # 注意 -g

# --- 真机 213 ---
ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes jenkins@10.22.67.213 \
  'cd ~/workbuddy/orgflow-devops && git rev-parse --short HEAD && docker ps --format "{{.Names}}\t{{.Status}}"'

# --- 部署（213 上）---
USE_GHCR=1 make deploy                                  # 全栈（render → 分批起 → 等健康 → 自检）
USE_GHCR=1 bash scripts/deploy.sh --service homepage    # 单服务
bash scripts/deploy.sh --help                           # 其余参数
bash scripts/check-arch-ips.sh                          # 固定 IP 文档一致性
```

`jobs` `jobs-test` `backup` `restore` `backup-verify` `lint` `test` `test-bats` `images-lock`
`images-pin` `test-groovy` `clean` `hooks` `identity-check`。

> 本仓库**不使用** `DOCKER_UID`（那是 `orgflow` Jenkins 仓库的约定）。`DOCKER_GID` 有，但用途不同：
> 它是宿主 `docker.sock` 的组 id，由 `deploy.sh` / `Makefile` / harness 探测后 export 给 agent 容器。
