# 配置管理

> 规程性质：配置项在哪、怎么改、怎么保持一致。配置的**值**不在仓库（`.env` 真值只在部署机）。

## 1. 配置项地图

| 配置类 | 位置 | 变更流程 |
|---|---|---|
| 服务编排 | `docker-compose.yml` / `docker-compose.ghcr.yml` | 改 → `make check` → PR → CI |
| 镜像版本 | `tests/images.lock` + compose pinned-at | 只走 `make images-pin` 三步，**禁手改 digest** |
| Jenkins 配置 | `config/jenkins.yaml`（JCasC 唯一真源） | 改 → DinD 用例验证 → PR |
| 网关路由 | `config/routes.yaml`（router 只灌配置） | 改 → `15_router`/`36_gateway_acl` 用例 → PR |
| 口令与密钥 | 部署机 `.env`（0600，不入库） | 首部署自动随机生成；轮换见使用说明 §5 |
| LDAP 目录 | `scripts/ldap-bootstrap.ldif` + `ldap_config/` 挂载 | 改 → `10_ldap`/`38_ldap_write` → PR |
| 文档 | `docs/` | 必登记（[文档规范](文档规范.md)） |

## 2. 基线与一致性

- **基线锚点**：`tests/images.lock`（源码↔镜像）+ `config/routes.yaml`（路由唯一真源）；
- **一致性核对命令**：`make check`（文档/配置/标签清单）+ `make test`（静态+行为自检）；
- **注意**：`out/` 是渲染产物目录，不能 `rm -rf` 整个目录再手工补（曾致路由数假红，
  见[经验教训](经验教训.md)）；重渲染用 `make render`。

## 3. 变更纪律

配置变更一律走 PR + 门禁；两处真源（JCasC/routes.yaml）改了必须同步对应的行为用例，
否则 `images-guard`/DinD 用例会拦——这套拦截面就是本文的执行机制。
