# 经验教训

> **这是本仓库教训的唯一真源。** 其它文档不再各写各的「踩坑清单」——它们只链接到这里。
> 每条教训都是真实事故换来的：写清**现象 → 根因 → 改成了什么规矩**。
> 与具体需求的强绑定事实（比如「A6 的必拒格为什么只有 1 个」）留在
> [requirements/](../requirements/README.md) 的现状栏里，此处只收可泛化的模式。

## 1. 门禁与红线

### 状态码 200 不能证明页面能用

首页书签值写成映射时，YAML 解析器**静默丢掉** `href`，前端 `new URL(undefined)` 抛
`TypeError` 整页白屏；而 `curl` 返回 200、HTML 里链接都在——只有真浏览器会炸
（#42）。改法不是修 YAML 就完事：判据改成 `GET /api/bookmarks` 每个书签必须同时有
`name` 和 `href`。**判据要不依赖页面状态码，直接断言数据形状。**

### 静态检查全绿、运行直接炸

`options { timestamps() }` 用了不在镜像里的插件，运行时让整条 pipeline 编译失败，
而当时的 1–5 条静态判据全部通过（#91）。第 6 条判据因此改成：`options {}` 里出现的
调用名必须在**运行时白名单**内，白名单直接抄 Jenkins 报错原文，不靠自己猜。
**判据的写法比判据本身重要。**

### 假红比漏报更浪费时间

- `migrate_identity.py --verify` 在 Windows 上 `normpath` 产出反斜杠而 allowlist
  用正斜杠 → allowlist 永不生效、`out/` 不被跳过 → `make test` 恒红 → 门禁被当噪音
  （#85，2026-11-11 已修：路径一律 `as_posix()` 归一）；
- 脱敏门禁上一版按「每文件×每规则」起进程，Windows Git Bash 上 ~3000 次进程创建，
  表现为「没有任何输出、退出码 1」——看起来像门禁拦住了，实际是门禁没跑完
  （`check-public-redaction.sh` 头注释）。

规矩：**门禁红先取证**——真缺陷 / 判据没跟上变化 / 环境差异，三类改法完全不同
（见 [AGENTS.md](../../AGENTS.md) §遇到红怎么办）。

### 123456 写进 README 的事故

README 曾直接写出目录初始口令，而那个值在部署机上真在用。脱敏门禁的
`password_re` 判据就是这条事故的化石：**公开仓的凭据不是「敏感」而是「已泄漏」**，
凡「明确在说口令」的上下文里出现弱口令形态即红。

### 反证必须两半

改坏一处 → 门禁必须红；恢复 → 绿。**只贴绿的那半不算验证**——历史上为修红
放宽断言或删用例的假绿，代价已经付过一次（[AGENTS.md](../../AGENTS.md)）。

### CodeQL 的告警打的是数据流，不是字面量

`py/clear-text-storage-sensitive-data` 对**变量名含 secret** 或 **crypto 源**
（如 `secrets.token_hex`）写文件的流都报——改成中性变量名没用，要用**中性值**；
测试代码里兄弟用例的 `secret` 夹具若是脱敏测试故意保留的，不要顺手「修」掉。
（PR #154 三轮红才定案。）

## 2. 测试与环境

### 持久卷跨轮泄漏：compose down -v 清不到别人建的卷

DinD 的守护进程存储在宿主持久卷 `m0-dind`；`nexus-deploy.sh` 自建的
`orgflow-devops_nexus_data` 不归 compose 管，teardown 清不掉 → 上一轮改过密的
Nexus 数据残留，下一轮新随机密码登录失败（PR #156）。规矩：**teardown 清单 =
compose 资源 + 脚本自建资源**，两者都要点名。

### 「TAP 一条都没输出」= 失败在 harness 早期

`grep -c "^ok"` 是 0 不是「全过」，是 bats 根本没开跑：镜像、compose up、入口脚本
炸在前面。先看 harness 早期日志，别去数用例。

### 同名容器不能并行

push 钩子的 DinD test-bats 与手动 test-bats 都叫 `orgflow-m0-test`，并行必撞
`docker run` Error 125，push 被钩子拦。规矩：**push 前先确认没有在跑的 m0-test**
（用 `docker ps -a --filter name=orgflow-m0-test`，不要 pgrep——它会自匹配误报）。

### 全新 Nexus 有两道默认墙

CE EULA 未接受时 REST 一律 403；匿名访问默认关闭。任何「新起的 Nexus」测试或
部署，先把 EULA 与匿名按 `scripts/72-nexus-setup-repos.py` 的幂等三步处理掉
（PR #151 定案）。另：PyPI simple 索引按 **PEP 503 归一化**只认连字符名，
下划线包名 404。

### curl 的 --resolve 不带端口就等于没写

`--resolve host:8443:ip` 只对 `https://host:8443/` 生效；URL 里少端口默认 443，
--resolve 不匹配 → 走真实 DNS → 环境里 443 无人监听 → curl(7) 连接拒绝。
症状是「连接拒绝」而不是「解析失败」，很误导（PR #151 第四轮）。

### 备份链路会被「移出 compose」静默打断

Nexus 移出 compose 后，`backup.sh`/`restore.sh` 里的 `compose ps/stop/start nexus`
必然报 `no such service`——而当时**没有任何判据能发现这种跨需求破坏**（#93）。
修法：服务运行时抽象 + 内容级门禁（缺 db 或 blobs 直接删包报错）。规矩：
**改一个服务的部署方式，先查谁在按服务名摸它。**

## 3. 部署与脚本

### 示例口令不能靠用户手改

`.env.example` 带示例占位值时，「cp 一份然后改掉」在现实中 = 示例值直接上生产
（2026-11-15 全新部署实测撞上）。`deploy.sh` 因此加了口令体检：`.env` 里
口令键为空或等于示例值时**自动重新随机生成**写回，用户真值绝不动（PR #154）。

### 「口令只在部署机 .env」是文档承诺，脚本必须兑现

`nexus-deploy.sh` 早期只认环境变量，文档却说口令在 `.env`——手工 `bash
scripts/70-nexus-deploy.sh` 时改密步骤被**静默跳过**，下游 401（PR #155）。
规矩：**文档承诺的取值路径，脚本要么实现要么在缺值时显式报错，不许静默跳过。**

### 「跳过」提示要当红看

`[nexus-deploy] NEXUS_ADMIN_PASSWORD 未设置，跳过改密` 是一条普通日志，
但它意味着后续所有带凭据的步骤都会失败。部署脚本里凡是「缺输入就跳过」的分支，
都必须把「跳过了什么、后果是什么」打出来（现在已做到）。

### healthy ≠ 能用

容器 healthy 只证明进程活着。验收必须打到端点：`deploy` 末尾的自检
（`auth /ping 200`、`jenkins /login 200` 等）与 `verify-*` Job 就是为此存在。
**部署 ≠ 验证**（[使用说明 §0 第 8 步](使用说明.md)）。

### 热加载的是 router 容器，不是宿主

「改路由不重启」由 `router` 容器 watch `routes.yaml` 后调 Caddy admin 接口完成；
宿主上跑 `make render` 只是看渲染结果，够不到 `caddy:2019`（#1 判据写成 bats
就是为了不混这两件事）。

### 防第二真源：用「文件没变」证明「没写」

路由 API 拒绝非法输入时，只看 400 分不清是「校验拦住了」还是「写坏了才报错」；
判据用 `routes.yaml` 的 sha256 前后一致来证明**真的没写**（#61）。

### `RETENTION_DAYS=0` 是拒绝，不是「静默不清理」

「静默不清理」和「清理策略没生效」在日志上无法区分——所以 0 被定义成明确拒绝
（非零退出）（#5）。同类原则：**能区分「没做」和「做失败」的地方，都要显式区分。**

### Windows 客户端工具的三个编码硬约束

`.bat` 必须 GBK+CRLF（LF 让 `goto`/`if` 块解析错乱）；`.ps1` 必须 UTF-8 带 BOM+CRLF
（无 BOM 中文被按 ANSI 读成乱码）；`certutil` 失败返回负数 HRESULT，cmd 的
`if errorlevel 1` 只认非负会误判成功——证书判断一律枚举 `Cert:\LocalMachine\Root`
（#47）。这三条无自动化断言，**只能靠人守**，是 D6 最脆的一格。

### `out/` 是产物目录，checkout 会带走它

`ca.org-devops.com/root.crt` 由 `ca-install.sh --export` 生成，不进 git；
`git checkout --` 还原工作树时被顺手清掉 → CA 分发 404（2026-11-15 实测）。
规矩：**验收清单里凡是产物路径，先确认产物存在再看端点。**

### 镜像上下文变了而 pins 没更新 = 部署到旧代码

`make deploy` 的 `images-guard` 就是拦这个：pinned-at 落后于镜像上下文最新提交时，
现在部署会拉到上一版镜像——拉取成功、健康检查通过、跑的却是旧代码。
修法固定三步：合并到 main → 等 Images 工作流 → `make images-pin` 回写（PR #153）。

## 4. 版本控制与身份

### git push 会给钩子导出 GIT_*

`git push` 导出的 `GIT_DIR` 让钩子链里的测试工具把 fixture 提交落进**被推的真分支**
（20 个提交同一秒落 HEAD，reflog 铁证），身份门禁随即拦下一切（PR #152 定案）。
修两层：测试自身的 git 调用剥掉 `GIT_*` 环境；钩子调重检查前 `env -u` 剥离。
规矩：**测试里的 git 操作必须与调用者环境隔离。**

### 提交身份会被环境变量悄悄覆盖

部署机账户的 `GIT_COMMITTER_NAME/EMAIL` 环境变量会覆盖仓库配置——漏设一次就被
identity 校验拦下重做。规矩：**在非交互环境 commit 一律显式注入 GIT_AUTHOR/
GIT_COMMITTER**（钩子与 `make identity-check` 是最后一道网，不是第一道）。

## 5. 工具链（AI 协作与远程操作）

这些是 AI 协作开发反复付学费的地方，写成硬规矩：

- **pwsh → ssh 的转义边界**：内联命令里的双引号会被链路剥掉，`grep -E "a|b"` 的
  `|` 会被当管道拆。复杂命令一律写成脚本文件传过去执行，不做内联 heredoc。
- **多文件批量 scp 会静默失败**：一次只传一个文件，传完对 md5。
- **管道吃退出码**：`python3 ... | tail -5` 的 rc 是 tail 的——失败照样「成功」，
  `&&` 链会继续把坏结果提交出去。关键步骤显式查 rc。
- **结构化文本比对先剥行尾**：`splitlines(keepends=True)` 之后拿原值比对，行尾
  `\n` 让所有判据永不匹配（PR #154 首轮 2 红根因）。
- **占位符是精确字符串**：环境占位符写错一个字符就是另一把钥匙——门禁会拦，但
  别靠门禁兜底。
- **本地没装工具就别本地校验**：本地 python 是 WindowsApps stub 时语法校验全部
  静默假成功，校验一律在远端做。
- **长输出取证走存档**：CI 日志/artifact 用脚本抓关键段存文件再读，不要在终端里
  凭肉眼捞。
