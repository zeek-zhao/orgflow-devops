## 3. 自建层 digest（tests/images.lock）

`tests/images.lock` 记录的是**本分支 CI 构建产物**的 digest，与 main 的 lock 无继承关系。
CI（`.github/workflows/build-images.yml`）构建 7 个镜像推 GHCR 后，`make images-lock` 从 registry 解析真实 digest 回填；人不许手改。

## 4. 回填流程（升级 / 首次构建）

1. 改动某个服务源码或配置 → `bash scripts/sync-build-context.sh` 同步构建上下文。
2. push 触发 CI 构建推 GHCR（镜像名 `m0-<svc>`）。
3. `make images-lock` 从 GHCR 解析 digest，回填 `tests/images.lock` 与 `config/images.env`。
4. `make check-all` 全绿后提交；`check-image-source.sh` 的上下文快照随 `make images-lock` 更新。

## 5. 允许删分支（AC-20）

删除 main 之外的任何分支后，本分支仍能独立 `build → push → deploy`：
Dockerfile、构建上下文（由 sync 脚本从真源生成）、CI workflow、上游登记表全部随本分支提交，不引用其他分支文件。
