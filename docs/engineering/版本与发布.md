# 版本与发布

> 状态：review ｜ 负责人：zeek.zhao ｜ 层级：规程（DOC-P-017）
> 镜像构建与流水线见 [M0 镜像与 CI](../M0-镜像与CI.md)，再分发义务见 [开源合规](../开源合规.md)。
> 本文是发布总纲：**版本语义 → 发布物 → 准入清单 → 锁定与回写 → 回滚 → 支持期**。

## 1. 版本语义

| 对象 | 命名 | 含义 |
|---|---|---|
| 镜像标签 | `24.04-vN` | 自建镜像的版本线，Ubuntu 24.04 基座 |
| 构建标签 | `sha-<7位>` | 每次构建的短 SHA 追溯 |
| 浮动标签 | `latest` | 便于人工查看，**部署不用它** |
| 部署引用 | `@sha256:<64位>` | 唯一可信锚点 |
| 里程碑 | M0 / M1 | 范围容器，不是时间盒 |
| tag | 发布点 | 与里程碑刻意不 1:1 |

包名形态 `ghcr.io/zeek-zhao/orgflow-devops/<组件>`；当前分发 13 个包
（12 个进 SBOM，另 1 个是测试镜像）。**部署只认 digest，不认标签**。

## 2. 发布物

| 类别 | 内容 |
|---|---|
| 镜像 | 自建 6 个 + 搬运的上游镜像，全部推 GHCR 且匿名可拉 |
| 许可证 | `LICENSE`、`THIRD_PARTY_NOTICES.md`、`licenses/` 全文 |
| SBOM | `out/sbom.spdx.json`（SPDX 2.3，`make sbom`） |
| CVE 账 | `out/cve/`（`make cve`，先出账不阻断） |
| 文档 | `docs/**` 由 `scripts/gen_docs_site.py` 编成对外站点 |
| 回滚 | 备份包三件套，见 [备份与恢复](../备份与恢复.md) |

## 3. 发布准入清单

```bash
bash scripts/check-public-redaction.sh .
make links
make docs-check
make sbom
make cve
make images-guard
make check-all
```

`make cve` 未装 trivy 时明确失败退出，不让「没扫」被当成「扫过且干净」。
`make images-guard` 报「已提交未构建」时**不许发版**：拉取会成功、健康检查会通过，
跑的却是上一版代码。

## 4. digest 锁定与回写

三步，顺序不能换（[M0 镜像与 CI](../M0-镜像与CI.md)）：

1. 提交并合并到 `main`，等 Images 工作流构建推送完成。
2. 本地 `git pull` 后 `make images-pin` 回写 GHCR digest。
3. `make images-guard` 复核上下文自 `pinned-at` 无改动。

`USE_GHCR=1` 部署必须 `--no-build`；`--build` 会撞 digest 锁定（#29）。
`tests/images.lock` 的 digest 是「这份源码对应哪个镜像」的唯一锚点，**不得改它来修红**。

## 5. 回滚

| 场景 | 动作 |
|---|---|
| 新版镜像起不来 | 回退 `docker-compose.ghcr.yml` 的 digest 到上一版并重新部署 |
| 配置改坏 | 回退 PR（Rebase 不 Squash），重跑 `make render` |
| 数据损坏 | 走 [备份与恢复](../备份与恢复.md) 的恢复流程与三件套校验 |
| 网关证书链断 | 从 `out/ca/` 重新导出根证书，不要删 `out/` 目录 |

回滚后必须重跑 §3 准入清单，不能只验「页面能开」。

## 6. 支持期与合规声明

- **当前不宣称符合 EU CRA 2024/2847**：五条差距（SBOM 只覆盖镜像、无漏洞处理时间线、
  无 90 天披露承诺、无支持期声明、未出具符合性声明）见 [开源合规](../开源合规.md) §9。
- SBOM → CVE → VEX 三段只落地第一段，后两段由 #133 立项，M0 不做，
  见 [开源合规](../开源合规.md) §10。
- 平台侧安全开关改完必须再 `GET` 比对状态，不信 `PATCH` 的 200，
  见 [开源合规](../开源合规.md) §11。
