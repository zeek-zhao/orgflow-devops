# 版本与发布

> 规程性质：镜像/仓库的版本语义与发布动作。本文不宣称符合 EU CRA 2024/2847
>（口径见[开源合规](../records/开源合规.md)）。

## 1. 版本语义

- 镜像 tag：`<服务>:<版本>-v<N>`（如 `jenkins:24.04-v3`），digest 是唯一锚点
  （`tests/images.lock`）；
- 仓库分支：`main` 可部署基线；改动一律经 feature 分支 + PR（不得直推 main）；
- M0/M1 是里程碑，不是版本号；需求基线以 REQ 编号冻结。

## 2. 发布准入（三步 + 门禁）

1. 改动合并进 `main`（Rebase 合并，必需检查全绿）；
2. 等 `Images` 工作流构建推送完成（Actions → Images）；
3. 部署机 `git pull` 后 `make images-pin` 回写 digest → `make check` → PR 合并。
   `make deploy` 的 images-guard 会拦「已提交未构建」——绿灯后镜像才可信。

## 3. 回滚

- 配置回滚：`git revert` 对应提交 → 重新走发布准入三步；
- 镜像回滚：`make images-pin` 前手工把 lock/compose 的 digest 指回旧值
  （唯一允许手改 digest 的场景，PR 说明里必须写明）；
- 数据卷不在回滚范围：回滚前先备份（[备份与恢复](备份与恢复.md)）。

## 4. 支持期

- `main` 持续维护；镜像 tag 保留最近 3 个版本，更早的按 GHCR 配额清理；
- 已发布 digest 的支持期 = 对应 images.lock 条目被引用的期间。
